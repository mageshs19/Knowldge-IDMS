## 2. Business purpose and flow

### Phase 2 business interpretation

The test now explicitly requires the original capital amount (Q-000013), the first event 0092 in legacy encounter order (Q-000023), and three distinct fatal missing-data outcomes (Q-000022). These are scoped simulated policies. They do not make the delivered conversion conform: the capital projection is still absent, maximum surrogate ID is still the selection mechanism, and two child-missing situations still share the same event SELECT +100 branch. The exact source flow below remains the evidence baseline.


The batch reads 21-byte stock-change requests (`WS-IN-NR-TIT-BC` 13 + `WS-NR-SUITE` 2 + `WS-OLD-CI` 6) and writes 1500-byte monthly mutation records. Product type is fixed to `1002`. For each request the original obtains its stock parent, walks event children until the first `0092`, decodes that event's form key and populates the order/output record. The target replaces that with one parent SELECT and one event SELECT, using `ORDER BY NR_ID_479EVEF DESC FETCH FIRST ROW ONLY` for event 0092. [IDMS L49–59, 86–89, 172–208; DB2 L34–44, 217–348.]

Unchanged material rules are visible: `NX-CPCRE-STOCK=0` chooses capital amount, otherwise interest amount; operation subtype 0 produces `MU`, every other subtype calls USERABEN; fixed issue/stock indicators are `1`, quantity 001, channel 10, bank DX; the reference is `CIR ` + operation code + space + incrementing 7-digit sequence; transaction reference is `X000000` +6 spaces; old CI is copied from input. The creation timestamp appends `01.01.01.000001` to the date. These are business rules, not incidental translation syntax. [IDMS L213–312; DB2 L353–475.] Input EOF ends the batch; every successfully treated record increments the output count. Target additionally reports total successful input READs. [IDMS L315–329; DB2 L478–494.]

**Demonstrated static behavior defect:** the target's capital branch reads `AM-CNDSTK-479BEFF` after `INITIALIZE DCLDZBEFFTV`, but the parent SELECT never populates that column. For a source parent with coupon-rank 0 and nonzero capital, it outputs 0 instead of the stored capital. It selects coupon-rank twice, which may be the copy/paste origin but does not prove intent. [DB2 L219–263, 393–399; IDMS L247–253.] No source code was changed in this analysis.
