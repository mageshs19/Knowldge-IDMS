## 2. Business purpose and flow

The job scans all securities and their events as of PARMDATE, writing 50-byte inventory-comparison records only when the final business state isC. DATE-IND0 uses the current date; a two-digit year greater than 60 maps to 19xx, otherwise20xx. A supplied date follows the existing input layout. ESDATMAS return0 supplies PARMDATE; any other return prints the bad date and calls USERABEN (source 119–148; target 209–238).

Each parent starts WS-STATUS at space. For events with date **≤ PARMDATE**, 0060 setsC and saves NR-ID-GOOD unless alreadyD; 0168 with CO-STATE-EVPRAN **not equal to 1** setsD and ends the child walk; 0217 setsS only from space. Future events do nothing. Thus0217 followed by0060 yieldsC, while0060 followed by0217 remainsC. Multiple qualifying 0060 events overwrite the saved key, so the **last encountered** creation CI wins. D suppresses output even after an earlierC.

Legacy encodes D termination by assigning artificial ERROR-STATUS0307 (source 198–211). Target preserves the state logic, uses SW-STATUS-D to exit the child loop, closes the cursor, then writes onlyC withoutD (target 262–339). Separating business rejection from a database status is appropriate to the visible flow; the added flag is redundant because existing WS-STATUS already storesD. There is no main update/checkpoint protocol.

## 7. Cursor lifecycle and transaction flow

Parent cursor opens once after the output opens, fetches all view rows, runs one complete child scope per row and closes on parent EOF (target 243–256/357–422). Its SQL has no WHERE or ORDER BY. An IDMS area sweep and unfiltered view scan have matching intent only if view coverage and downstream order requirements are established.

Each parent resets WS-STATUS to space and initializes the child group. Child OPEN0 sets its NOT-EOC flag. The four parent-key fields remain in DCLDZBEFFTV; FETCH writes DCLDZEVEFTV. This preserves the current parent without FIND CURRENT or added key storage. Child processing stops on SQL100 or business D. Both normal exits close the child cursor; only state C withoutD is written afterward (target 262–339).

Parent EOF state is independent because child FETCH/CLOSE changes SQLCODE. Each SQL statement's own EVALUATE is immediate; there is no intervening SQL before its status test. No COMMIT/ROLLBACK occurs in the main; WITH HOLD does not create a checkpoint. Missing SQLERROR and external routines prevent proof of failure cleanup, transaction side effects and handler non-return.
