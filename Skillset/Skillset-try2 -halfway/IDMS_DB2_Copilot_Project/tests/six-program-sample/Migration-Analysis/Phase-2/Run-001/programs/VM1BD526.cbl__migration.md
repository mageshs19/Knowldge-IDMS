### Source-based analysis and evidence retained

**OBSERVED:** The program reads a sequential securities-operation record from DD020 and takes one business action per successfully read physical input record. With `CO-STCIRC-OORD = '1'`, it creates an event of type `0168`, service `0219`, beneath stock/product type `1002`. Every other circulation value goes to the modification branch. The modification replaces a form/business identifier in an existing matching event. Both branches are part of the same checkpointed batch flow. There is no amount calculation or output data-file WRITE in either listing; visible external effects are diagnostic DISPLAYs, the final target totals and abort calls. Original VMBD205I defines the circulation character at physical line 1314 (file position 885).

The original uses three **different** LRF requests: `STORE ... ST-VMBEVEF`, `OBTAIN FIRST ... ALL-VMBEVEF-BY-VMBEFF` with event/service filters, and `MODIFY ... MO-VMBEVEF`. Their supplied paths establish a parent lookup, child insertion, child traversal and current-child modification. The nearby original comment mentioning `VMBWCEF` is not evidence of a VMBWCEF write on the selected path: the actual `ST-VMBEVEF` path only obtains VMBEFF and stores VMBEVEF (Schema/VMBTS07.txt L182–189).

The target replaces those requests with a four-key singleton parent SELECT, an explicit child INSERT, a ranked singleton child SELECT, and UPDATE by the selected generated child ID. It introduces audit fields and sequence-generated identity. The original's first qualifying child is changed to the child with greatest `NR_ID_479EVEF`; equality of those choices is **UNRESOLVED**, because the supplied set declaration has no order definition (case C004).

The exact retained routing rule is:

```cobol
0149:     ADD +1 TO TELLER.
0150:     IF CO-STCIRC-OORD = '1'
0151:     THEN PERFORM 210-STORE-EFF
0152:     ELSE PERFORM 220-MOD-EVEF
0153:     END-IF.
```

Target physical 217–220:

```cobol
0217:     IF CO-STCIRC-OORD = '1'
0218:     THEN PERFORM 210-INSERT-EVFF
0219:     ELSE PERFORM 220-UPD-EVEF
0220:     END-IF.
```

Original business flow is initialization → restart positioning → read next input → choose insert/update → after 100 processed records update FFRECAB and COMMIT → repeat → final checkpoint and FINISH. The target follows the same normal batch shape, with an incomplete/completed restart flag, a cumulative read count, and SQL COMMIT after updating its restart row. Whether all error paths terminate before the checkpoint depends on missing runtime code.

**INFERRED from the observed normal order:** the intended recoverable work unit appears to be a physical input record, grouped into 100-record database transactions, with a final smaller transaction. This does not establish an approved business unit or guaranteed atomicity through unavailable wrappers. The target's completion-abend and its 28-character key representation are changes that need their own policy/compatibility evidence.

## 6. Working-storage and helper assessment

### Phase 2 scoped reassessment

Q-000032 now chooses a count-only restart policy for the rehearsal. Consequently KY-RESTART and WS-INPUT-KASBONS are **removal candidates under this test policy**: neither is used to select or verify resumed work. Their two 1200-byte allocations must not be relabelled as a mandatory persistent buffer. The actual source is unchanged and still copies these areas. Keep the cumulative position and independent batch count as two required roles, but assess reusing existing 15-digit NB-READ for the cumulative position instead of allocating a second narrow total. During skip, NB-READ must remain the fixed extent and positioning reads must not advance it; ordinary successful processing may advance it afterwards. This is an uncompiled proposal, not a change already tested on a mainframe. Q-000020 makes the existing-input-alias alternatives concrete for the hypothetical layout only; the real converted COPY remains missing. For Q-000009’s run-scoped choice, the observed once-per-invocation timestamp must survive its uses; whether one logical run spans restarts remains undefined. No particular formatting buffer is mandatory solely because of that state lifetime.
