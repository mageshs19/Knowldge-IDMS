## 2. Business purpose and flow

The visible job reads 40-byte issue records from EMISSIONS-I and writes 90-byte security records to EFFEKT-O. It derives the as-of date from a parameter or current date, mapping two-digit years below80 to 20xx and the rest to 19xx (source 164–177; target 266–279). For each input it calls VM9BC50T QUERY001 with key selector2. The returned issue key identifies an owner; the returned currency is used in the output. The program traverses that owner's securities and each security's events.

For each security, SW-168 starts at0. It becomes1 only for event code **0168**, embedded operation **91**, an event date strictly before the cutoff, and an event date at least maturity minus one month. January rolls to December of the prior year; the day is retained without calendar clamping (source 282–298; target 404–419).

A separate reduction selects CI. A 0060 event at or after the cutoff is ignored. The first earlier0060 sets marker1 and its CI. A 0092 event can replace that choice when its embedded transfer date exceeds the current marker and remains strictly below the cutoff. Equal transfer dates keep the first encountered candidate. The chosen CI and redemption flag are independent: a qualifying redemption without a usable creation/transfer can produce CI000000 (source 263–315; target 350–447).

After all events, SW-168=1 emits one output row. Target adds read/security/output display counters, initializes the output group per security and removes LAATSTE-OPD, which the complete legacy main only assigns/resets and never reads. It retains the material predicates after date/key conversion; representation, order and service validity remain conditions on equivalence.

## 7. Cursor lifecycle and transaction flow

The owner SELECT runs before parent OPEN. Its equality predicate returns the same owner-code value into its input host while sequence/date input values remain intact. Parent cursor DZBEFFC1 uses all 3 owner fields, FOR READ ONLY and WITH HOLD, with no ORDER BY. Successful OPEN sets parent NOT-EOC; each successful FETCH processes the entire child scope before the next parent FETCH (target 338–376,527–594).

The child cursor parameters use all 4 security key components in **DCLDZBEFFTV**, while child FETCH writes **DCLDZEVEFTV**. Parent key/output fields therefore survive without an additional saved-key area. For every parent, marker/CI/SW-168 and child/output groups are reset; child OPEN establishes its own state, FETCH loops until child EOF, CLOSE runs, then optional output is written. Zero children leave SW-168=0 and emit nothing. Child order is NR_ID_479EVEF DESC; full set-order and loading evidence is absent.

Each statement tests SQLCODE immediately in its own paragraph. Child SQL runs after the parent EVALUATE already chose WHEN0; the outer loop subsequently uses its own flag. This avoids incorrectly reading child CLOSE SQLCODE as the parent FETCH result. Error handling is unresolved because SQLERROR may issue SQL or return. There is no main COMMIT/ROLLBACK; WITH HOLD is not evidence of a checkpoint or safe restart.

## 13. COBOL/SQL standards and defects

Demonstrated facts are the unused/duplicate staging groups, missing build dependencies, conflicting event-key declarations and missing order/DDL evidence. They are not compiler diagnostics. Conditional risks are a returning SQLERROR, non-EUR fetched dates, and a surrogate order that does not match the business-sensitive legacy order. Retained edges include non-calendar month subtraction, amount/output capacity and unchecked service return fields. Do not present these as newly introduced executed failures without data and business intent.

SQL scopes and END-EXEC blocks were inspected, not precompiled. PROGRAM-NAME and SQL-LOCATION depend on missing SQLERRWS. Qualified hosts distinguish parent/child fields with shared names. The generated event ID is fetched but unused in COBOL; removing it from SELECT/FETCH while retaining required ORDER BY is a possible later refinement subject to actual SQL preparation. Parent singleton uniqueness is not proved by a DECLARE TABLE or sheet label. No application code was modified.
