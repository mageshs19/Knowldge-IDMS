## 2. Business purpose and flow

The original reads a 20-byte archive parameter record, sweeps VMBFAS forms through LRF, and writes 530-byte archive extract records for subscriptions/cancellations. Its business filter is exactly:

```cobol
IF (DA-CPTA-FORM-AS OF VMBFAS < DA-ARCH-YMD AND
    DA-CPTA-FORM-AS OF VMBFAS NOT = '00000000') OR
   (DA-CR-FORM-AS OF VMBFAS < DA-ARCH-YMD AND
    DA-CPTA-FORM-AS OF VMBFAS = '00000000')
```

This chooses accounting date when nonzero, otherwise creation date, with a **strictly before** cutoff; equality is excluded. Each selected form increments the 11-digit packed counter, copies the raw VMBFAS record into 478-byte F-FORM, writes counter+issue 7 digits+stock 13 digits trailer, and keeps 2 switches/filler blank. [IDMS L87–94, 167–172, 186–203.]

The target pushes the filter into the cursor's WHERE using Db2 DATE columns and `01.01.0001` as the zero-accounting date sentinel, orders by surrogate `NR_ID_479BFAS ASC`, fetches 84 columns, reconstructs the legacy output layout and writes one output for each successful fetch. The target still writes 530 bytes and does not delete/archive away the Db2 rows. This is an extract, not an update/restart job. [Target L280–374, 442–556, 589–879.]

The linkage DATE-IND branch and century window (year>60→19, else 20) are retained, but the archive cutoff comes from the file, not that calculated system date. Preserve this distinction; don't silently replace the file business date with CURRENT-DATE. Empty date input calls USERABEN; normal empty result set writes no forms. [Old L148–179; target L394–423.]

## 7. Cursor lifecycle and transaction flow

DECLARE `DZBFASC1` has 84 columns, strict date filter, ORDER BY NR_ID ASC, FOR READ ONLY and no WITH HOLD. Startup sets both cutoff hosts from the archive file and opens once. OPEN 0 sets N; OPEN other calls SQLERROR. Loop FETCH initializes the DCLGEN, sets N, fetches one, processes only SQLCODE 0; FETCH 100 sets Y. Other codes record SQL-LOCATION 2200 and call SQLERROR. At EOF, the cursor closes, any nonzero CLOSE goes to handler; count diagnostics follow and output file closes. [Target L366–374, 416–423, 429–587, 882–889.]

Resetting DCLGEN before FETCH does **not** lose the already opened cursor cutoff: Db2 uses host parameter values from OPEN. Fetch results are therefore allowed to reuse the parameter host storage after OPEN. Any future CLOSE/REOPEN would require restoring cutoff hosts first. No SQL runs during row formatting, so immediate SQLCODE-based loop may avoid the flag if error policy is restructured correctly. An unseen returning SQLERROR can otherwise leave N and cause another FETCH; OPEN failure can reach FETCH; handler contract is essential.

Normal path has no Db2 DML write, COMMIT, ROLLBACK, checkpoint/restart row. The source defined LR path contains no hidden write. External file WRITE is not a transactional Db2 effect. Row ordering by surrogate ID is new and not proved equivalent to IDMS area order; output counter makes ordering observable. Uniqueness and concurrency snapshot requirements require DDL/bind options.

## 12. Restart and buffer replacements

### Restart

This visible program and selected LR path have no restart table, checkpoint, Db2 business write or resume marker. WS-TELLER is only a transient output sequence/count, not a persisted checkpoint. Input is one archive control record followed by the database cursor. No WITH HOLD exists, and even a held cursor would not be a persistent restart position. Supplied global replacement names cannot be applied to locally unused FF records without actual scope evidence.

### Buffer and file output

REC-FORM is a transient 530-byte output record. It is not a persistent Db2 buffer table. Every eligible Db2 row produces a file WRITE; failure/restart output disposition belongs to the job/downstream contract. No exactly-once file processing is proved.
