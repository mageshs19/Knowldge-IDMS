## 2. Business purpose and flow

**Header comment:** "STOCKAGE FORMULAIRES VMBZ : COUPONS". The program stores **coupon payment forms** (VMBFC = form coupon) under a coupon "SI" index owner (VMBSIC, keyed by order CIO + order ID). The input is the same 1200-byte VMBD205I layout, read through the `-OORD` (order) redefines.

### 2.1 Main line

| Legacy | DB2 |
|---|---|
| BEGIN-PROG: ACCEPT-DATE, OPEN-FILES (BIND, `READY AR-VMBFRM4 / AR-VMBRFFB UPDATE`), TREAT-FFRECAB, first READ | 100-BEGIN-PROG: 140-ACCEPT-DATE (+ timestamp, + run date DD.MM.CCYY), 150-OPEN-FILES, 800-RESTART-CONTROL (includes the first read) |
| TREAT-PROG UNTIL EOF | 120-TREAT-PROG UNTIL EOF |
| END-PROG: ADD TELLER, FIND CURRENT + MODIFY FFRECAB, CLOSE, FINISH | 130-END-PROG: CLOSE, 830-PROCESS-COMMIT (CO_ID='1'), 3 statistics DISPLAYs |

### 2.2 Per-record logic (TREAT-PROG, L122-203)

```
INITIALIZE LR (numeric→0, alnum→spaces)
fill VMBSIC key   (NR-CIO-OORD, NR-DI-OORD)
fill VMBFC        (key: CIO, ID, DA-CR, OPG, OPD, NS-LINE; 20 data fields; DA-PAY = run date)
STORE LR WHERE ST-VMBFC-BY-VMBSIC          -- find owner SIC by CALC, store FC under it
IF VMBSIC-NOT-FND
     STORE LR WHERE ST-VMBSIC              -- create owner
     IF 'VMBSIC-EXIST' → abend  ELSE
     STORE LR WHERE ST-VMBFC               -- store FC; owner currency = SIC just stored
     IF 'VMBFC-EXIST'  → abend
ELSE IF 'VMBFC-EXIST' → abend
every 100 records: ADD TELLER TO NS-REC-FF-IN, FIND CURRENT FFRECAB, MODIFY, COMMIT
read next
```

### 2.3 Business invariants

| ID | Invariant |
|---|---|
| BIZ-255-01 | Every input record produces one VMBFC row. There is no code filter. |
| BIZ-255-02 | The owner VMBSIC (CIO + ID) is created **on demand**, only for the first coupon of that order. |
| BIZ-255-03 | The VMBFC payment date `DA-PAY-EVPRCP` = **run date** (PARM or system date), not an input field. |
| BIZ-255-04 | `DA-CPTA` (accounting date) and `NR-IS` are initialised to zero. In DB2, DA-CPTA = `'01.01.0001'` (DATE-02). |
| BIZ-255-05 | Duplicate coupon (same CT-RK + CIO + ID + DA-CR + OPG + OPD + NS-LINE): **intended** fatal, **actual** legacy behaviour silently ignored (see §8, CONFLICT C-01). |

## 7. Cursor lifecycle and transaction flow

**No cursors.** One singleton SELECT (owner probe) and INSERTs.

```
per record:
  SELECT DZBSICTV by (CIO, ID)
    0   → INSERT DZMBFCTV                  (-803 fatal)
    100 → INSERT DZBSICTV (-803 fatal) → INSERT DZMBFCTV (-803 fatal)
  TELLER+1 ; if TELLER > 99 → 830 (UPDATE DZ01RSTV, COMMIT)
```

**LRS-02-b (NEW) — owner probe.** The LR path does `FIND owner → STORE member`, and the program falls back to "store owner then member" on OWNER-NOT-FND. Two DB2 conversions are valid:

| Variant | Code | Used by |
|---|---|---|
| (a) probe | SELECT owner by PK; 100 → INSERT owner; then INSERT member | **VMDZ1255** |
| (b) insert-tolerant | INSERT owner, -803 → CONTINUE; then INSERT member | VMDZ1250 (SI* tables) |

Both are equivalent in a single-writer batch. Variant (b) is one SQL call shorter and race-free. The engine should choose **one** (recommend (b)), unless the legacy explicitly abends on OWNER-EXISTS after OWNER-NOT-FND, which is unreachable anyway.

## 8. Error and business-outcome decision table

### 8.1 CONFLICT C-01 — legacy literal mismatch (production-critical)

| Path returns (VMBTS09) | Program tests | Match? |
|---|---|---|
| `VMBSIC-EXISTS` (ST-VMBSIC, schema L279-283; ST-VMBFC L284, ST-VMBFC-BY-VMBSIC L289) | `'VMBSIC-EXIST'` (L173) | **No.** LR-STATUS is X(16); `'VMBSIC-EXIST    '` ≠ `'VMBSIC-EXISTS   '` |
| `VMBFC-EXISTS` (ST-VMBFC, ST-VMBFC-BY-VMBSIC) | `'VMBFC-EXIST'` (L178, L186) | **No** |

**Effect in production [INF]:**
- A path-returned keyword sets LR-STATUS with a zero ERROR-STATUS, so AUTOSTATUS does not abort.
- A **duplicate coupon is silently skipped**. The STORE did not happen, and the program continues.
- The DISPLAY/USERABEN branches are dead code.

| Situation | Legacy actual | Legacy intended | VMDZ1255 |
|---|---|---|---|
| New coupon, owner exists | store FC | same | INSERT FC → PASS |
| New coupon, new owner | store SIC + FC | same | INSERT SIC + FC → PASS |
| Duplicate coupon (e.g. the same input line twice, or a rerun without a restart row) | **skip silently** | abend | **abend (-803 → SQLERROR)** |
| LR-ERROR / SQL error | abort (AUTOSTATUS) | abort | SQLERROR |

**Engine rule ERR-03 (NEW):** compare every `LR-STATUS = '<literal>'` in the program with the keywords that the path can actually RETURN (from the subschema). If a literal matches no path keyword:
1. Flag it as **CONFLICT**.
2. Do not silently convert it.
3. Default to the **actual** legacy behaviour (status not caught → `-803 CONTINUE` for a 1205-derived keyword).
4. Raise a question for the business owner (Q-15).

VMDZ1255 chose the intended behaviour. Both choices must be visible in the report.

### 8.2 Other outcomes

| Event | Legacy | DB2 | Equivalent? |
|---|---|---|---|
| Owner SELECT error | — (FIND inside the path → LR-ERROR → abort) | DISPLAY + SQLERROR | Yes |
| Input shorter than the restart count | positioning stops at EOF, the next READ fails [UNK] | reads past EOF [UNK] | Both undefined (D-03) |
| Completed-run rerun | positions to the end, processes 0, OK | USERABEN | V-01 |

## 10. LR path semantics (VMBTS09, LR CURRENCY NO RESET)

| Keyword | Body | Statuses | DB2 |
|---|---|---|---|
| ST-VMBFC-BY-VMBSIC | FIND FIRST VMBSIC by CALC KY-SIGIFC OF LR (0326 → VMBSIC-NOT-FND); STORE VMBFC (1205 → VMBFC-EXISTS) | VMBSIC-NOT-FND, VMBFC-EXISTS | SELECT owner + INSERT member |
| ST-VMBSIC | STORE VMBSIC (1205 → VMBSIC-EXISTS) | VMBSIC-EXISTS | INSERT owner |
| ST-VMBFC | STORE VMBFC (1205 → VMBFC-EXISTS); the owner of set VMBSIC-VMBFC is taken from **currency** | VMBFC-EXISTS | INSERT member with FK = key of the owner just inserted |

**LRS-05 is confirmed:** a currency-dependent store (no FIND in the path) becomes an INSERT whose FK columns are filled from the **same working-storage values that built the owner key in the same record cycle**. The engine must track which owner was made current last (here: the SIC stored one statement earlier).

Paths in VMBTS09 that this program does not use, but which will matter for other programs:
- OB-VMBSIC-VMBFC: owner → EACH member.
- OB-VMBSIC-VMBFC-PRIOR: reverse order, so ORDER BY DESC.
- SWEEP-VMBSIC-VMBFC: area sweep, which becomes a full-table cursor ordered by PK.
- MO-VMBFC, ER-VMBFC.
- ER-VMBSIC: ERASE ALL MEMBERS, which becomes DELETE members then owner, or ON DELETE CASCADE.
- The coupon/event paths.

## 12. Restart: FFRECAB variant B

| Aspect | Variant A (VM1BD250/252) | **Variant B (VM1BD255)** | VMDZ1255 |
|---|---|---|---|
| Row creation | STORE at the first checkpoint | **STORE at start** if not found | INSERT at start |
| Checkpoint re-access | OBTAIN CALC + MODIFY | **FIND CURRENT** + MODIFY | UPDATE by key |
| Commit trigger | `TELLER NOT < 100` at the start of the cycle | `TELLER > 99` after processing | same as legacy |
| Retention NB-DAY | 15 | **7** | **7** (copied from legacy) |
| Positioning | `PERFORM 110 UNTIL TELLER NOT < NS`, with STOP01 at EOF | `PERFORM READ VARYING … UNTIL EOF OR TELLER > NS`, **no STOP01** | NB-READ TIMES, no EOF check |
| Program key | 'VM1BD25x-A' | 'VM1BD255-A' | 'VMDZ1255' phase 1, date = run date |

**RST-07 (NEW): NB_DAY_RS must be copied from the legacy `MOVE n TO NB-DAY-FF`**, not hard-coded to 15.
