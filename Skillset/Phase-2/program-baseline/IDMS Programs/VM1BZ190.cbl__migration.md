# IDMS Programs/VM1BZ190.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base. Rule IDs refer to `../../generic/` and earlier program reports. **NEW** marks a rule first seen here (provisional ID `<CAT>-Z190-n`).
>
> - Evidence labels: [OBS] observed, [INF] inferred, [UNK] unknown.
> - Legacy references `Lnnn` are **physical file lines** (285 lines), verified by a numbered listing. Cols 1-6 step by **10** with inserted seqs (000041, 000171-172, 000181-185, 000472, 001122-127) and a block numbered in steps of **1** (001971-002023, L192-229), plus deletion gaps. Do not compute from seq. Examples: seq 001700 = L174, seq 002080 = L238, seq 002790 = L263.
> - DB2 references are `seq NNNNNN` (cols 1-6 of VMDZ1190, 291 lines; seq has suffixes such as 017402, 034003).
> - Schema-Listing / VMBTS07.txt / CSV / copybook / DCLGEN references are physical lines of those files.
> - Mapping confirmed by header: legacy "RECHERCHE DU NOMINAL DANS LA D.B. TITRES POUR LES MEP MANUELLES" (L10-11) = DB2 "SEARCH FOR NOMINAL VALUE IN THE SECURITIES DATABASE FOR MANUAL MEPS" (seq 001003-001103).
> - Closest DB2 sister: **VMDZ4310** (same author JAINRG, 2026/04; same `WS-TOTAL-INPUT S9(11) COMP-3` + `DISPLAY 'TOTAL INPUTS ='` + `INITIALIZE VMDZ510I`) [OBS grep]. Unlike VMDZ1190, VMDZ4310 does route `WHEN 100` / `WHEN OTHER` to SQLERROR.

## 2. Business flow

```
MAIN (L169-172)        PERFORM D-PROG ; PERFORM TRAIT THRU TRAIT-EX UNTIL E-O-F ; PERFORM F-PROG ; STOP RUN
D-PROG (L174-177)      ACCEPT-DATE ; OPEN-FICHIER ; LECT-MEP
ACCEPT-DATE (L251-257) DATE-IND='0' → ACCEPT DATE6R-WS FROM DATE, MOVE CORR → DATE8 → DATE6 ; else DATE6 ← DATE6-LS
                       (result never read again — dead in legacy, L-03)
OPEN-FICHIER (L259-267) OPEN INPUT MEP, OUTPUT MEPCPT ; PROGRAM-NAME ← 'VM1BZ190' ; BIND ×3 ; READY RETRIEVAL
LECT-MEP (L270-281)    READ MEP AT END FIN-FICH ← HIGH-VALUES ; not EOF → WS-NR-ST-NEW ← NR-ST-COUP-X, WS-NS-DB-NEW ← NS-DB-GDIFC
TRAIT (L179-189)       IF WS-KEY-NEW ≠ WS-KEY-OLD → WS-KEY-OLD ← NEW ; OBTAIN-VMBEFF            (cache per key)
                       IF EFF-FOUND AND AM-CND-COUP = 0 → AM-CND-COUP ← AM-CN-STOCK (LR storage) ; CO-TST-COUP ← 'R'
TRAIT-EX (L191-197)    IF CO-DEV-COUP = 'BEF' → CONVERSION-EUR ; WRITE MEPCPT-REC FROM VMBD510I ; LECT-MEP
CONVERSION-EUR (L199-209) AM-INTGR-COUP and AM-CND-COUP each via CALL-GE9RLEU1 (S9(13)V99 work field)
CALL-GE9RLEU1 (L211-228)  caller 'VM1BZ190', BB 'GERLEU01', 'P', CO-DEV-IN ← CO-DEV-COUP ; CALL
                       CO-RETURN ≠ '0000' → 3 DISPLAYs (STOP02) + CALL USERABEN ; else WS-AM ← AM-OUT
OBTAIN-VMBEFF (L230-242) EFF-FOUND ← TRUE ; VMBEFF key ← SPACES/'1002'/NR-ST-COUP/NS-DB-GDIFC
                       OBTAIN FIRST VMBTL07-R01 WHERE ALL-VMBEVEF-BY-VMBEFF
                       LR-STATUS = 'VMBEFF-NOT-FND' → EFF-NOT-FOUND (any other status = found)
F-PROG (L245-249)      CLOSE MEP MEPCPT ; FINISH
```

DB2 flow: main line seq 016002-016402 (F-PROG inlined: CLOSE + `DISPLAY 'TOTAL INPUTS ='` + STOP RUN). 1000-D-PROG (seq 016602-017103) moves PROGRAM-NAME, GET-TIMESTAMP, ACCEPT-DATE, OPEN, READ. 2000-TRAIT (seq 017302-028603) = TRAIT + TRAIT-EX merged; **`INITIALIZE DCLDZBEFFTV` runs before the key-break IF** (seq 017402, D-01). SELECT result: `WHEN 0` found, `WHEN OTHER` not found (seq 024602-027202, D-02).

## 12. Restart

Not applicable in either version [OBS]: no FFRECAB/DZ01RSTV, no COMMIT, no skip loop, READY RETRIEVAL only. A rerun recreates MEPCPT from MEP and is idempotent (RST-* rules, COMMIT-every-100, LEN 15/143 n/a). PARM DATE-IND/DATE6-LS does not influence output in either version (L-03).

### 15.2 New rules

| Rule | Statement | Guide |
|---|---|---|
| **KEY-Z190-1** | **NEW.** Key-break cached LR OBTAIN (`IF KEY-NEW NOT = KEY-OLD … OBTAIN`) relies on IDMS LR storage persisting between iterations. In DB2 the DCLGEN host structure **is** the cache: `INITIALIZE DCL<view>`, key moves and SELECT must all sit inside the key-break branch; nothing may reset the host fields outside it. Gate: any INITIALIZE of a DCLGEN whose SELECT is conditional. | 04 |
| **ERR-Z190-1** | **NEW.** A singleton SELECT replacing an LR OBTAIN maps only SQLCODE 100 to the business not-found status; `WHEN OTHER` must PERFORM SQLERROR (legacy LR-ERROR aborts under AUTOSTATUS). Grep signature: `WHEN OTHER` followed by `SET …NOT-FOUND`. Current hit: VMDZ1190 only. | 04 |
| **LRO-Z190-1** | **NEW.** Owner→member path (`ALL-<MBR>-BY-<OWNER>`: OBTAIN CALC owner / IF set EMPTY / OBTAIN EACH member) used only for **owner** fields, with the program testing only `<OWNER>-NOT-FND` → owner-only singleton SELECT (no member table). Record per status: LR-FOUND ≡ 0; `NO-<MBR>-FND` (untested) ≡ 0 in DB2 but stale LR storage in legacy → variant, needs sign-off. If the program tests a member status, add an `EXISTS`/COUNT probe on the member FK. | 04 |
| **PLAT-Z190-1** | **NEW.** `PERFORM P THRU P-EX` where P-EX holds live statements may be merged into one paragraph only after verifying no GO TO / other PERFORM targets P-EX or P's internal labels. | 04 |
