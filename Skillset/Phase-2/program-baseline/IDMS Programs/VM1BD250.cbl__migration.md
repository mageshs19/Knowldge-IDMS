# IDMS Programs/VM1BD250.cbl — IDMS to DB2 Migration Analysis

> **Purpose of this file.** This file is a knowledge base for one program, written for a downstream AI or Python conversion engine. ## 2. Business purpose and flow

**Business purpose** (header comment): "STOCKAGE FORMULAIRES VMBD : EFFECTEN". The program stores security (effecten) operation forms (*formulaires*) from a daily input file into the database. Each input record is one operation line. The general code (OPG) and detail code (OPD) select which form type and which records are written.

### 2.1 Glossary (Dutch/French → meaning)

| Term | Meaning | Term | Meaning |
|---|---|---|---|
| PROVISIE | provision / funding | INTEKENING | subscription |
| ANNUL-INTEKENING | subscription cancellation | NEERLEGGING | deposit |
| TERUGTREKKING | withdrawal | OMRUILING | exchange (multi-line block) |
| VERVANGING | replacement | TERUGKOOP | buy-back / redemption by repurchase |
| TERUGBETALING | repayment | POSITIONEREN | position (skip) input on restart |
| VERWERK | process | LEES | read |
| VUL | fill (build record buffer) | TELLER | counter |
| STOCKEREN | store | GLOBAAL | global (block header) |

### 2.2 Main line (legacy L97-103 / DB2 L191-196)

| Step | Legacy | DB2 |
|---|---|---|
| 1 | 100-INITIALISATIE: date, BIND/READY, restart (FFRECAB), first read | 100-INITIALISATIE: timestamp, date, OPEN, restart (DZ01RSTV), first read |
| 2 | 200-VERWERK-VMBD205I UNTIL EOF | 200-VERWERK-VMDZ205I UNTIL EOF |
| 3 | 800-TEST-FFRECAB (final checkpoint) | 800-PROCESS-COMMIT (final checkpoint, flag complete, COMMIT) |
| 4 | FINISH (commits), CLOSE | 300-END-PROGRAM (statistics DISPLAY, CLOSE) |
| 5 | STOP RUN | STOP RUN |

### 2.4 Exchange-block (OMRUILING) control logic — business critical

```
IF OPG='53' AND OPD='71' AND NR-REFORD-OORD = SAVE-NR-REFORD-OORD
   CONTINUE                              *> same block as previous line
ELSE
   SET WRITE-GLOBAL-OMRUILING TO TRUE    *> new block (or non-exchange line)
```

- 260: if WRITE-GLOBAL, perform 265, which writes the block header (FORM 0221 + SITE + FTE) and then **SET NOT-WRITE-GLOBAL-OMRUILING TO TRUE** (legacy L441).
- Every line then writes a VMBFTEL detail under the current VMBFTE (LR path `CREATE-VMBFTEL-FOR-VMBFTE` uses `FIND CURRENT VMBFTE` → currency-dependent).
- `SAVE-NR-REFORD-OORD` holds the **previous** record's order reference. 900-LEES moves the current reference to SAVE before reading the next record. 100-INIT sets it after the first read.
- The DB2 version keeps the switch logic in 200 but **omits the reset in 265** (D-01).

### 2.5 Business invariants the converted program must preserve

| ID | Invariant |
|---|---|
| BIZ-250-01 | One input record = one processing unit. The checkpoint count is the number of input records processed, including skipped/unknown codes. |
| BIZ-250-02 | FORM rows for 0030/0219/0220/0221/1816 must be **new**. A duplicate is a fatal data error. FORM 1818 (replacement) **may already exist**. |
| BIZ-250-03 | SI* owner rows (SIAS, SIDN, SIR, SIAR, and legacy SIRT/SITE/SIRV) are **shared** across forms. Duplicates are expected and silently accepted. |
| BIZ-250-04 | A child detail row (FAS, FDN, FR, FAR, and legacy FRT/FTE/FRV/MESS) must have its parent(s) present. A missing parent is fatal. |
| BIZ-250-05 | The exchange block writes exactly one global header per block (first line). |
| BIZ-250-06 | Annulment (52) always carries a security number: NR-ST is forced from input (legacy comment at L294). |
| BIZ-250-07 | Repayment (320) copies NS-CPAID-GDIFRV → NS-CPAID-GDIFAR (DB2: NS-INFSPD-479BFAR, mapping CSV L135). DA-INFSD is "no date". |

## 7. Cursor lifecycle and transaction flow

**Cursors:** none. The program is insert-only, and the only SELECT is a singleton (restart row). The engine needs no DECLARE/OPEN/FETCH/CLOSE for this program.

**Unit of work**

```
START ─ SELECT DZ01RSTV
        ├─ 100 (fresh) → INSERT DZ01RSTV(CO_ID='0', NB_READ=0)   [not yet committed]
        └─ 0   (restart) → CO_ID='1' ? USERABEN : skip NB_READ records
LOOP  ─ per record: business INSERTs
        every 100 records → UPDATE DZ01RSTV(NB_READ=n, CO_ID='0') ; COMMIT
EOF   ─ UPDATE DZ01RSTV(NB_READ=total, CO_ID='1') ; COMMIT ; CLOSE ; STOP RUN
ERROR ─ SQLERROR (assumed ROLLBACK + abend) → work back to the last COMMIT is undone,
        including the restart row update → restart resumes exactly at NB_READ+1
```

- The business inserts and the checkpoint update are in the **same unit of work**, so restart is exactly-once at record granularity. This is the same guarantee as legacy (MODIFY FFRECAB + COMMIT).
- If the program fails before the first COMMIT, the restart-row INSERT is rolled back too, so the next run is treated as fresh. This is correct.
- Commit interval: 100 records (a hard-coded literal; DB2 L360 still has a commented-out test value of 2). Same as legacy.

## 9. OCCURS and REDEFINES

- No OCCURS is used in the converted logic.
- REDEFINES are used for typed views of the input record. The DB2 code consistently uses the numeric `-R` redefines (`NR-CIO-FORM-AS-R 9(6)`, `CT-OPG-FORM-AS-R 99`, `CT-OPD-FORM-AS-R 99`, `DA-CREA-FORM-AS-R 9(8)`) when moving to DECIMAL/DATE host variables, and the alphanumeric base fields (`CT-OPG-FORM-AS PIC XX`) for dispatch comparisons.
- **Engine rule (HLP-04):** when a target column is numeric/DATE and the source field is X(n) with a 9(n) `-R` redefine, use the redefine.
- The input copybook has multiple business-view redefines of the same bytes (FORM-AS / MESS-RE / GDIFC / OORD / POKB / OPER / COUP / PAY). The program uses FORM-AS, OORD (NR-REFORD-OORD) and GDIFRV fields only.
- DB2 working storage: `DA-CCYYMMDD-R REDEFINES DA-CCYYMMDD` (CCYY/MM/DD) feeds `MOVE CORR` into `DA-DD-MM-CCYY`.

### 10.2 Normalization semantics

1. **"OF LR" key reuse.** The path WHERE uses key fields already present in the LR buffer, filled earlier by the program (e.g. 221 fills VMBSIAS before CREATE-VMBSIAS, and the same buffer serves CREATE-VMBFAS-FOR-VMBSIAS). In DB2 there is no shared buffer, so each child host structure gets **explicit FK columns** filled from the same input fields.
2. **Owner existence check.** IDMS FIND by CALC → NOT-FND. In DB2 this becomes RI (-530). In this program the owner was inserted (or found as a duplicate) immediately before, so NOT-FND/-530 cannot happen in normal operation. It remains as a safety net.
3. **Set connection** (automatic membership assumed) becomes FK columns. There are no CONNECT/DISCONNECT verbs in the active code.
4. **Order of operations is preserved:** owner first, then form, then child.
5. **Currency-dependent path (FIND CURRENT).** CREATE-VMBFTEL-FOR-VMBFTE relies on VMBFTE stored in 265 for the first line of the block. Under `LR CURRENCY NO RESET` the currency survives across lines. A DB2 equivalent would need the parent key kept in working storage (helper needed). This is moot here because FTEL was dropped.

## 12. Restart and buffer replacements

### 12.1 FFRECAB → DZ01RSTV

| Aspect | Legacy FFRECAB | DB2 DZ01RSTV |
|---|---|---|
| Key | NM-ID-FF 'VM1BD250-A' + DA-CR-FF (DAT-WS CCYYMMDD) + NS-SET-FF 0 | NM_ID_RS_PROGRAM 'VMDZ1250' + DA_CR_RS (DATE 'DD.MM.CCYY' from DAT-WS) + NB_ID_RS_PHASE 1 |
| Position | NS-REC-FF-IN (records processed) | NB-READ in TE_CH_RS_DATA (bytes 1-15) |
| Restart data | none | KY-RESTART X(1200) (diagnostic only) |
| Completion flag | **none** | CO_ID_RS '0' running / '1' complete |
| Retention | NB-DAY-FF 15 | NB_DAY_RS 15 |
| Other init values | CT-SET '1', CT-REC 'A', counters 0 | TE_CH_RS_DATA_LEN 1215 |
| Created | STORE at first checkpoint | INSERT at start (committed at first COMMIT) |
| Updated | OBTAIN CALC + ADD TELLER + MODIFY at each checkpoint | UPDATE at each checkpoint (absolute NB-READ, not additive) |
| Restart detection | OBTAIN found | SELECT SQLCODE 0 |
| Positioning | PERFORM 110 UNTIL TELLER ≥ NS-REC-FF-IN | PERFORM 110 NB-READ TIMES |
| Short input on restart | STOP01 | STOP01 |
| Rerun completed day | no-op success | **USERABEN** (V-01) |

### 12.2 Counting equivalence proof

- **Legacy.** TELLER is incremented at the start of 200 for each processed record, and its value is added to NS-REC-FF-IN at the checkpoint. NS-REC-FF-IN therefore equals the total processed records.
- **DB2.** WS-NB-INPUT-UPD-I is incremented on every successful read. The checkpoint runs in 200 *before* the next read, so the count equals the records processed. The EOF read is not counted.
- **Restart.** Both versions skip exactly N records, then read record N+1. Equivalent.

### 12.3 Buffer / work-area replacements

- The IDMS LR buffer (VMBTL06-R01 element records) is replaced by **per-table DCLGEN host structures**, each INITIALIZEd before it is filled. The engine must emit `INITIALIZE DCL<view>` before each fill, because NOT NULL columns must not contain low-values or garbage.
- There is no buffer object or external work-area use in this program (Q-08 is not applicable here).

## 15. Reusable cases, exceptions and open questions

### 15.1 Automation recipe (how the engine converts this program class)

1. **Detect the class.** Batch, `PROTOCOL MODE IS BATCH-AUTOSTATUS`, a `SCHEMA SECTION`, and `OBTAIN CALC FFRECAB` → apply the **FFRECAB restart template** (RST-01…RST-07).
2. **Strip IDMS platform code** (PLAT-01) and add `SQLERRWS`, `SQLCA`, one DCLGEN include per target view, and the `SQLERROR` include at the end of the PROCEDURE DIVISION (PLAT-02).
3. **For each** `OBTAIN|STORE|MODIFY|ERASE <LR> WHERE <path>`: look up the path in the subschema source and classify it (LRS-01 owner/form store, LRS-02 child-for-parent store, LRS-05 currency store, LRS-09 decommissioned).
4. **Emit** one `01-INSERT-<obj>` paragraph per target view, with the SQLCODE EVALUATE built from the legacy status test that follows the LR call:
   - statuses tested with **CONTINUE** → `WHEN -803 CONTINUE`;
   - statuses tested with **IDMS-STOP** → fatal.
   - **Decide per call site, not per path** (lesson from D-02).
5. **Replace the fill paragraphs.** `INITIALIZE DCL<view>`, then move input fields per the mapping CSV, apply DATE-01/DATE-02 to every DATE column, AUD-01 to the audit columns, and LRS-03 to the FK columns.
6. **Preserve the business control flow** (dispatch, switches, SAVE fields) **verbatim**, including every SET/MOVE on control switches (lesson from D-01).
7. **Generate the statistics counters and the end DISPLAY** (optional convention).

### 15.2 Exceptions specific to this program
- The 280 duplicate tolerance on FORM (call-site-specific status policy).
- The exchange-block switch.
- The 8 dropped records.
- The 230 NR-ST override.
- The 320 field rename NS-CPAID → NS-INFSPD.
