# IDMS Programs/VM1BZ170.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base. Rule IDs refer to `../../generic/` and earlier reports; **NEW** marks a rule first seen here (provisional ID `<CAT>-N170-n`).
>
> - Evidence labels: [OBS] observed, [INF] inferred, [UNK] unknown.
> - Legacy references `Lnnn` are **physical file lines**. VM1BZ170 numbers cols 1-6 in steps of **10** (not 100). It has inserted lines at L4 (`000031`) and L16-18 (no seq). So physical = seq/10 + 1 for seq 000040-000140, and **seq/10 + 4** from seq 000150 on. Verified: 000530 = L57, 001700 = L174, 002050 = L209.
> - DB2 references are `seq NNNNNN` (cols 1-6 of VMDZ1170; seq/100 = physical line).
> - Closest DB2 relatives: the **VMDZ1140** template (same author/month, `READ-MEP`, `820000-GET-TIMESTAMP`, restart LEN 143) [OBS grep]. The DZBEFFTV 4-column probe + `HELP-NR-ID-STOCK-CD` + `NS-DB-TEMP` block is cloned from VMDZ1555/1565/1575/1595 (XPG-01).

## 2. Business flow

```
D-PROGRAM (L101-114) DATE-IND='0' → ACCEPT DATE6R-WS FROM DATE ; else DATE6 ← DATE6-LS (DDMMYY)
                     YMD-WS ← YYMMDD ; SS-WS ← 20 if YMD-WS < 600000 else 19 → DATE-WS CCYYMMDD
PROGRAMME (L116-121) D-PROG ; TRAIT UNTIL SWEOF1=1 ; F-PROG ; STOP RUN
D-PROG (L123-166)    BIND ; READY 2 areas ; OPEN INFIL1
                     FFRECAB key ← PROG-VERSION + DATE-WS + NS-SET 0 ; OBTAIN CALC FFRECAB
                       found     → PERFORM LECTURE VARYING NBR-REC-READED UNTIL EOF OR > NS-REC-FF-IN
                       not found → init FFRECAB (CT-SET '1', CT-REC 'A', NB-DAY 7) ; STORE FFRECAB
                     not EOF → READ first record
                     EOF     → NBR-REC-READED − 2 < NS-REC-FF-IN → DISPLAY 'FICHIER INPUT CONTIENT MOINS…' ; CALL USERABEN
                     NBR-MODIFY, NBR-REC-READED ← 0
TRAIT (L168-196)     KY-EFFECT ← '1002' + SPACES + NR-ST-COUPON(13) + NS-DB-COUPON(2)
                     OBTAIN FIRST VMBTL07-R01 WHERE OB-VMBEFF
                       'VMBEFF-NOT-FND ' → nothing
                       else IF NS-ID-COUPON > NX-CPFDU-STOCK → NX-CPFDU ← NS-ID-COUPON ; MODIFY … MO-VMBEFF ; NBR-MODIFY+1
                     NBR-REC-READED+1 ; NBR-MODIFY = 50 → NS-REC-FF-IN += NBR-REC-READED ; FIND CURRENT/MODIFY FFRECAB ; COMMIT ; reset
                     READ next
F-PROG (L198-203)    CLOSE ; NS-REC-FF-IN += NBR-REC-READED ; FIND CURRENT + MODIFY FFRECAB ; FINISH
```

DB2 flow: D-PROGRAM is identical (seq 017000-018300) plus timestamp and DA-DD-MM-CCYY. D-PROG runs 800-RESTART-CONTROL and then a guarded first READ-MEP (seq 019800-020500). TRAIT builds the key in DCLDZBEFFTV and runs 1000-SELECT-BEFF → 1100 IF → 1110 UPDATE, commits when `NBR-MODIFY = 50`, then READ-MEP (seq 020800-023400). F-PROG does CLOSE, DISPLAYs, final commit.

## 10. LR semantics

| LR request | Path (VMBTS07) | Legacy statuses | DB2 |
|---|---|---|---|
| `OBTAIN FIRST … WHERE OB-VMBEFF` | `OBTAIN FIRST VMBEFF WHERE CALCKEY EQ KY-EFFECT OF VMBEFF OF LR`; `ON 0326 RETURN VMBEFF-NOT-FND`; `ON 0000 NEXT` (L118-123) | LR-FOUND = record in WS (**all fields, incl. NX-CPFDU**); VMBEFF-NOT-FND; LR-NOT-FOUND cannot occur (no LR WHERE) [INF]; LR-ERROR = other → abort | singleton SELECT on full CALC key: 0 = found, 100 = NOT-FND, OTHER = error. **The INTO list must hold every field read afterwards → LRO-N170-1.** |
| `MODIFY … WHERE MO-VMBEFF` | `FIND CURRENT VMBEFF; MODIFY VMBEFF` (L91-95) | currency comes from the OBTAIN | UPDATE by CALC key (DZBEFFTV has no surrogate, Q-69) SET NX_CPFDUSK + audit (LRM-01, AUD-02) |
| CALL PROCEDURES INFOCOMP/INFODCOM on VMBEFF (Schema-Listing L1321-1323) | — | — | ignored (PROC-01) |
| `LR CURRENCY NO RESET` (VMBTS07 L5) | — | no carry-over state is used | n/a (RST-LR-02 not triggered) |

The 4-column SELECT is the correct **owner-existence probe** of LRS-11 in VMDZ1555/1565/1575/1595, where nothing is read from the row. VMDZ1170 reused it for an OBTAIN whose data **is** read (XPG-01). Grep result: VMDZ1170 is the only VMDZ program that references NX_CPFDUSK in an UPDATE without selecting it. VMDZ1623 correctly SELECTs NX_CPAIDSK before its UPDATE (seq 022900-024700) [OBS].

## 13. Defects & variants

| ID | Severity | Location | Description | Fix (retain legacy) |
|---|---|---|---|---|
| **D-01** | **High** | 1000-SELECT-BEFF seq 043500-044800; 1100 seq 046500 | `NX_CPFDUSK_479BEFF` is not in the SELECT INTO. The host keeps 0 from `INITIALIZE DCLDZBEFFTV`, so `NS-ID-COUPON > 0` is true for every found stock with rank ≥ 1. Effects: (a) **NX_CPFDUSK is overwritten even when the input rank is lower → next-coupon-payable regresses**; (b) equal ranks are re-updated with new TS_UPDATE/ID_USERID; (c) NBR-MODIFY is inflated → commits come earlier. Legacy semantics = max(current, input). This is a clone of the 4-column probe (XPG-01); it is unique among VMDZ [OBS grep]. | add `NX_CPFDUSK_479BEFF` to SELECT/INTO (LRO-N170-1) |
| **D-02** | **Medium** | seq 006600, 027200 | Restart key uses the constant 'VMDZ1170' instead of PARM PROG-VERSION (X(11); DB2 column CHAR(8)). Several runs per day with different PROG-VERSION values share one restart row. The second run either abends (CO_ID_RS '1') or skips NB-READ records of a different file. | decide per Q-67; map PROG-VERSION or confirm a single run per day (RST-N170-1) |
| **D-03** | **Medium** | 810 seq 029900-030300 | Legacy short-file check (DISPLAY + CALL USERABEN, L157-164) is dropped and there is no EOF guard. File 1 record short: silent success with CO_ID_RS '1'. ≥ 2 short: READ after EOF → status 46 runtime abend [INF] with no business message. | after the loop: `IF VMDZMEPI-EOF` → legacy DISPLAY texts (program name VMDZ1170) + 810000-CALL-USERABEN (ERR-N170-1, ERR-02) |
| D-04 | Low | seq 033700 vs 031300 | TE-CH-RS-DATA-LEN 15 at commit, 143 at insert. KY-RESTART is truncated; only NB-READ is read back, so there is no functional effect. | 143 |
| D-05 | Info | seq 044800 | singleton SELECT without FETCH FIRST 1 ROW ONLY (LRO-01) | safe if unique (Q-69) |
| D-06 | Info | seq 048000, 046200, 001100-001700 | SQL-LOCATION 1100 in paragraph 1110. 700-* paragraphs set no location. Paragraph name typo `1100-UPDTAE-BEFF`. Header text cloned ("KASBONS", TB names). | cosmetic |
| D-07 | Info | seq 004800, 006700, 007700-009000, 021000 | dead MAX-TS-TIMESTAMP, DA-YYMMDD, DA-DDMMCCYY; redundant NS-DB-TEMP and INITIALIZE HELP-NR-ID-STOCK-CD | cosmetic |

## 15. Rules and open questions

### 15.1 Reused rules

### 15.2 New rules

| Rule | Statement | Guide |
|---|---|---|
| **LRO-N170-1** | **NEW.** LR/DML OBTAIN → singleton SELECT: the INTO list must contain **every record field the program reads** between the OBTAIN and the next overwrite (IF operands, MOVE sources, COMPUTE operands), not only the key columns. The key-only probe (LRS-11) is valid only when no field of the row is read. The engine must compute the read-set per OBTAIN and fail generation if a read field is unmapped. | 04 |
| **CNT-N170-1** | **NEW.** When the legacy commit trigger counts **updates** (`NBR-MODIFY = 50`), keep that counter, its increment point (only after a successful UPDATE) and its limit. Do not substitute the template "every 100 input records". The restart position still counts input records (BIZ-CNT-01). | 02 |
| **RST-N170-1** | **NEW.** If the legacy FFRECAB key name comes from the PARM (e.g. `PROG-VERSION`) instead of a literal, the engine must flag it. Replacing it by `CS-PROGRAM` changes restart isolation between runs. NM_ID_RS_PROGRAM is CHAR(8) and the legacy field is X(11), so a mapping decision is required (Q-67). | 02 |
| **ERR-N170-1** | **NEW.** A legacy restart-positioning sanity abend (e.g. "input contains fewer records than already processed" + CALL USERABEN) is a program-defined abend (ERR-02). Port it after the NB-READ skip loop as `IF EOF → legacy DISPLAYs + CALL USERABEN`. The template's unguarded loop is not enough. | 02, 04 |
