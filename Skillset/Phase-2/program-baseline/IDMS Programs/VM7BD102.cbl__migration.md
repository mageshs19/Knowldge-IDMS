# IDMS Programs/VM7BD102.cbl — IDMS to DB2 Migration Analysis

> **Purpose.** Knowledge base for one program pair: legacy VM7BD102 vs the manual DB2 conversion VMDZ7102. Written for a downstream conversion engine and its reviewers.
>
> **Evidence labels:** `[OBS]` observed in source, `[INF]` inferred, `[UNK]` needs a human answer. **NEW** marks a rule first proposed here (provisional ID `<CAT>-V7102-n`).
>
> **Line references:** legacy = **physical file lines** (`L`), from a full line listing. Seq steps by 10 with inserts (000151-000153, 000281, 000461-000468, 001051, 001931, 001941-001946, 002541) and deletions (000090, 000800-000860, 001710-001810, 002420-002530, 002570-002580), so seq is never used (L204 = 002010 `OBTAIN FIRST`, L253 = 002630, L274 = 002840). DB2 = `seq NNNNNN` (cols 1-6). Cols 1-6 **wrap after 990007** inside paragraph 720; from there on refs use the 8-digit cols 73-80 value (`seq 01xxxxxx`), which is monotonic. Schema-Listing, VMBTS07, DCLGEN, copybook and mapping-CSV (`Modified - Field Mapping … V 1.0_Manual.csv`) refs are physical lines.
>
> **Pairing.** Legacy L7-9 "ARCHIVAGE : SELECTIE VAN DEFINITIEF VERNIETIGDE EFFECTEN (DAT ARCH EN INPUT) EN EFFECTEN MET VOLGNUMMER > 01" = VMDZ7102 seq 000907-001100, verbatim. "DEFINITIEF VERNIETIGDE" occurs in exactly these two files [OBS grep]. Same FDs (DD005 20 / DD010 154), REC-EFFECTEN length, LS-PARAM, paragraph names, STOP 01 texts. **Confidence: High.**

## 2. Business flow (legacy, physical lines)

```
MAIN (L142-146): PERFORM BEGIN-PROGRAMMA THRU EXIT; PERFORM NIVEAU-EFFECT UNTIL LR-STATUS = 'VMBEFF-EOA';
                 PERFORM EINDE-PROGRAMMA THRU EXIT; GOBACK
NIVEAU-EFFECT (L148-152): BEGIN-EFFECT; PERFORM BEHANDELING UNTIL LR-STATUS = 'VMBEVEF-EOS'; EINDE-EFFECT
BEGIN-PROGRAMMA (L155-208)
  LS-DAT-IND = '0' → ACCEPT YYMMDD FROM DATE, YY > 60 → 19 else 20; else LS-DATE-DMY8 (DDMMCCYY)   L157-172
  WS-DA-CYMD ← DMCY; WS-DA-CYMD-MIN03 = date - 3 months  (both never used afterwards, L-02)         L173-186
  OPEN INPUT DAARCH OUTPUT EFFECTEN; READ DAARCH INTO VMBZ270I-REC AT END DISPLAY + USERABEN       L188-194
  DISPLAY 'DATE ARCH : ' DA-ARCH-YMD; CLOSE DAARCH                                                 L195-196
  PROGRAM-NAME ← 'VM7BD102'; BIND RUN-UNIT/VMBEFF/VMBEVEF; READY AR-VMBEFF1 RETRIEVAL              L198-202
  OBTAIN FIRST VMBTL07-R01 WHERE SWEEP-VMBEFF-VMBEVEF  (→ 1st VMBEFF + 1st event | EOS | EOA)       L204
BEGIN-EFFECT (L211-226): REC-EFFECTEN ← SPACES; EFF-VMBEFF ← VMBEFF (96 raw bytes)               L213-214
  WS-WRITE ← 'Y' if NS-DB-STOCK OF VMBEFF > 01 else ' '; WS-OCC ← 0                               L216-222
BEHANDELING (L229-257)  -- one event, set order
  WS-OCC + 1; > WS-MAX (100) → '##&&VM7BD102 - STOP 01' + 3 DISPLAYs + CALL USERABEN               L231-238
  WS-VMBEVEF(WS-OCC) ← VMBEVEF (48 raw bytes)                                                       L239
  0168 AND CO-STATE-EVPRAN ≠ '1' AND DA-CR-EVENT-PROD < DA-ARCH-YMD → EFF-SW-VERN, WS-WRITE ← 'Y'    L243-249
  OBTAIN NEXT VMBTL07-R01 WHERE SWEEP… (→ next event | VMBEVEF-EOS)                                 L253
EINDE-EFFECT (L260-278)
  WS-WRITE = 'Y' → WS-TELLER + 1; EFF-TELLER ← WS-TELLER                                            L262-264
      PERFORM VARYING WS-IND 1..WS-OCC: EFF-VMBEVEF ← WS-VMBEVEF(WS-IND); WRITE EFFECTEN-REC        L265-269
  OBTAIN NEXT VMBTL07-R01 WHERE SWEEP… (→ next VMBEFF + 1st event | EOS | EOA)                      L274
EINDE-PROGRAMMA (L281-288): FINISH; CLOSE EFFECTEN.   IDMS-ABORT (L290-293): CLOSE EFFECTEN; COPY IDMS IDMS-STATUS
```

**DB2 (VMDZ7102):** BEGIN-PROGRAMMA identical incl. dead MIN03 block, plus `600-GET-TIMESTAMP`, `END-READ`, `PROGRAM-NAME ← CS-PROGRAM` (seq 670507-675407); main: `INITIALIZE DCLDZBEFFTV`, 710 OPEN / `720 FETCH UNTIL DZBEFFC1-EOC` / 730 CLOSE, EINDE-PROGRAMMA, GOBACK (seq 661807-666400). FETCH 0 → `ADD 1 WS-NB-BEFF-COUNT` + NIVEAU-EFFECT (seq 01100007-01120007). NIVEAU-EFFECT = BEGIN-EFFECT, `INITIALIZE DCLDZEVEFTV`, 810 / `820 UNTIL DZEVEFC1-EOC` (FETCH 0 → BEHANDELING, seq 01760007) / 830, EINDE-EFFECT (seq 666607-670207). BEGIN-EFFECT/BEHANDELING/EINDE-EFFECT keep every legacy IF; raw MOVEs replaced by `PERFORM 100-MOVE-BEFF-OUT` / `200-MOVE-EVEF-OUT`; EINDE-EFFECT adds `INITIALIZE EFF-VMBEVEF` and `ADD 1 WS-NB-OUTPUT-COUNT` (seq 802208, 802408). ## 10. LR semantics

- **SWEEP path** (VMBTS07 L157-164): two-level EACH iteration, no IF EMPTY. `OBTAIN FIRST` returns the first VMBEFF with its first VMBEVEF; `OBTAIN NEXT` re-enters at the inner EACH (L253) and, after `VMBEVEF-EOS`, the next call (L274) backs up to EACH VMBEFF [INF LRF re-entry; identical to VM4BD305, Q-116]. `LR CURRENCY NO RESET` (VMBTS07 L5) keeps the area position. DB2 = outer owner cursor + inner per-owner member cursor (LRO-V4305-1 confirmed, second hit).
- **Empty set**: VMBEFF + `VMBEVEF-EOS` → BEHANDELING not entered (UNTIL tested first), EINDE-EFFECT still runs: WS-TELLER is incremented for NS-DB-STOCK > 01 although 0 records are written (L-01). DB2 identical (zero FETCHes). The stale VMBEVEF LR area is not read (contrast LRO-Z260-1).
- **LR area as record image**: VMBEFF/VMBEVEF in the LR area are full IDMS record images (IDMS-RECORDS MANUAL + COPY IDMS LR), so `MOVE VMBEFF` copies all 96 bytes incl. FILLERs and packed bytes untouched. DB2 has no image; it must be rebuilt from columns (HLP-V7102-1). Non-migrated bytes (FILLERs, NR-ID-GOOD XX, sign nibbles) are the risk points.
- **Order**: the selection (WS-WRITE, EFF-SW-VERN = "any qualifying row") is order-free (ORD-V4300-1), but the **output record sequence** is the walk order on both levels → outer and inner ORDER BY are output-visible (ORD-V7102-1).
- **Date compare**: legacy group DA-CR-EVENT-PROD (alphanumeric) < DA-ARCH-YMD 9(8); DB2 numeric 9(8) < 9(8) (seq 800407). Legacy spaces < any digit date; DB2 0001-01-01 → 0 < date → same selection; output bytes differ (D-06). 9999-12-31 → 99999999 excluded in both.
- Stale-LR-area STORE/MODIFY (LRO-N595-1): n/a (read-only). CALL PROCEDURES INFOCOMP/INFODCOM (Schema-Listing L1321-1324, L1385-1388) ignored (PROC-01).
