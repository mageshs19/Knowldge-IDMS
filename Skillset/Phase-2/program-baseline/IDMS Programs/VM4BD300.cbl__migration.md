# IDMS Programs/VM4BD300.cbl — IDMS to DB2 Migration Analysis

> **Purpose.** Knowledge base for one program pair: legacy VM4BD300 vs the manual DB2 conversion VMDZ4300. Written for a downstream conversion engine and its reviewers.
>
> **Evidence labels:** `[OBS]` observed in source, `[INF]` inferred, `[UNK]` needs a human answer. **NEW** marks a rule first proposed here (provisional ID `<CAT>-V4300-n`).
>
> **Line references:** legacy = **physical file lines** (`L`). In this file physical line = seq/100 exactly (L1 = 000100, L133 = 013300 `OBTAIN FIRST VMBEFF`, L171 = 017100 `FIND CURRENT`; verified by search, no inserts). DB2 = cols 1-6 sequence numbers (`seq NNNNNN`; non-uniform suffixes 04/05/03, not = line × 100). Schema-Listing, VMBTS07, DCLGEN, copybook and mapping-CSV refs are physical lines.
>
> **Pairing.** Legacy header L6 "DETERMINATION DES TITRES EN CIRCULATION" = VMDZ4300 seq 000804 "DETERMINATION OF SECURITIES IN CIRCULATION" (only VMDZ hit for "DETERMINATION" [OBS grep]). The pair also shares FD UITBST DD005 90 bytes, the UITREC layout, PARAM-DATONLY, and CALL-VM9BC50T with key '3'. **Confidence: High.**

## 10. LR / DML semantics

- **Area sweep with currency restore.** OBTAIN VMBEVEF (same area AR-VMBEFF1, Schema-Listing L1384) moves the *current of area* to the event. `FIND CURRENT VMBEFF` (L171) resets current of run-unit/area/sets to the owner, so `OBTAIN NEXT VMBEFF WITHIN AR-VMBEFF1` continues after the owner and not after its last event [INF IDMS currency rules]. In SQL the outer cursor keeps its own position → FIND CURRENT has no equivalent and is dropped (LRO-V4300-1).
- **Shared 0307.** `DB-END-OF-SET` is one ERROR-STATUS value for both loops. It works in the legacy only because FIND CURRENT (L171) resets ERROR-STATUS to 0000 before the outer `UNTIL` is tested again [INF]. DB2 uses two flags (correct).
- **Empty set.** OBTAIN FIRST member 0307 → inner PERFORM not entered → SW-KREATIE 0 → no record (same as DB2 FETCH 100).
- **Order sensitivity of NEXT-VMBEVEF** [INF from L181-211]: (a) SW-VERNIETIGD → final 'Y' if *any* qualifying 0168/0060 exists → order-independent; (b) SW-KREATIE → order-independent; (c) 0092 strict-max of HULP-DA-UB-TRANSF below today → order-independent except **ties**; (d) the first past 0060 (LAATSTE-DA = 0 sentinel) sets CI only if seen before any qualifying 0092; but any later qualifying 0092 overrides it (> 1), and if a 0092 came first the 0060 is skipped → the final CI is order-independent **unless there are ≥ 2 past 0060 events and no qualifying 0092**, or 0092 ties. → D-03 Low, ORD-V4300-1.
- **Early stop.** The legacy stops the walk on 'Y' (no OBTAIN NEXT, L213); DB2 stops FETCHing (UNTIL clause) and closes. Equivalent. CALL PROCEDURES INFOCOMP/INFODCOM (Schema-Listing L1321-1324, L1385-1388) → ignored (PROC-01); record REDEFINES R2/R3/CT-RK-TGOOD (L1345-1348, L1403) unreferenced.

### 15.2 New

| Rule | Statement | Guide |
|---|---|---|
| **LRO-V4300-1** **NEW** | Direct-DML area sweep `OBTAIN FIRST/NEXT <owner> WITHIN <area>` with `FIND CURRENT <owner>` before each NEXT → one cursor `SELECT … FROM <owner table> FOR READ ONLY` (all rows: check that the table holds only that area's occurrences). | **HLP-V4300-1** **NEW** | When an IDMS X(n) field is overlaid by a program-local COMP-3 group (e.g. NR-ID-GOOD X(20) → HULP-NR-ID-GOOD), the DB2 overlay must match the **migrated** column format: take length and layout from the DCLGEN and the data-migration spec, never from the CSV alone; a CSV/DCLGEN length mismatch (CHAR(20) vs CHAR(28)) blocks generation. Keep any value guards inside the branch that uses the field. | all |
| **ORD-V4300-1** **NEW** | Order-sensitivity classification for member loops: switches set on "any row" and strict-max accumulators are order-free (except ties); "first row" sentinels (`IF X = 0 → take`) are order-dependent. Generate ORDER BY per ORD-01 only for the order-dependent part and record the residual tie cases as a test. | 04 |
