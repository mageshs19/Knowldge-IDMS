# IDMS Programs/VM1BZ130.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base. Rule IDs refer to `../../generic/` and earlier program reports. **NEW** marks a rule first seen here (provisional ID `<CAT>-N130-n`).
>
> - Evidence labels: [OBS] observed, [INF] inferred, [UNK] unknown.
> - Schema-Listing / CSV / VMBTS09.txt references are physical lines of those files.
> - Legacy references `Lnnn` are **physical file lines**, verified by search. The cols 1-6 sequence steps by **10**, not 100. Line = seq/10 + the number of inserted seqs before it (000041, 000181-184, 001091-095, 001741, 001871-872, 002171-172). Examples: `OBTAIN FIRST` seq 001710 = L179; `OBTAIN NEXT` seq 002450 = L258.
> - DB2 references are `seq NNNNNN` taken from **cols 73-80** of VMDZ1130 (seq/100 = physical line). Cols 1-6 agree up to 027500. After that they lag by 100, because 027400 is duplicated at physical L275-276.
> - Closest DB2 sister: **VMDZ1015**. Same author (V. Mahajan, April 2026), same `2100/2200/2300` cursor paragraphs, same `WS-KY-COUPON` DISPLAY, same DISPLAY-only FETCH error branch (seq 061100-061400) → XPG-01 clone [OBS grep]. Read-only class, like VM1BD510/590 (no DB write).

## 2. Business flow

```
MAIN     (L136-139) D-TRAIT ; TRAIT UNTIL SWEOF = 1 ; F-TRAIT ; STOP RUN
D-TRAIT  (L141-155) PROGRAM-NAME ← 'VM1BZ130' ; BIND ×3 ; READY AR-VMBCOUP RETRIEVAL
                    OPEN DD010 in, DD020/DD030/DD040 out ; AM-INTGR-COUPON ← 0 ; LECTURE
TRAIT    (L157-160) D-COUP ; TRAIT-COUP UNTIL SWEOF = 1 OR CLE-COUP ≠ ACLE-COUP
D-COUP   (L169-186) ACLE ← CLE ; CTR-RECYC ← NB-PAYRE-COUPON ; CTR-DB ← 0
                    KY-COUPON ← SPACES ; NR-ID-STOCK-CD ← NR-ST-COUPON (13) ; NS-DB ; NS-ID
                    OBTAIN FIRST VMBTL09-R01 WHERE OB-VMBCOUP-VMBEVCP                  (L179)
                    W-MT ← AM-INTGR-COUPON ; W-CV ← GR-IDISSU-STOCK (X4 + 9(4) + X8)     (L180, L183)
                    RECH-EVTS UNTIL 'VMBCOUP-NOT-FND' | 'NO-VMBEVCP-FND' | 'NO-MORE-VMBEVCP'
RECH-EVTS(L250-258) CAUSE ∈ neg set → CTR-DB −1
                    else IF NR-ID-GDIFC = 0 AND DA-CR-GDIFC = 0 → CTR-DB +1
                    OBTAIN NEXT VMBTL09-R01 WHERE OB-VMBCOUP-VMBEVCP
TRAIT-COUP (L188-240), per record:
  NEG op:  CTR-DB > 0 → CTR-DB −1 ;
              op 97: W-MT = AM-IND AND W-CV1 = SL-NR-PROD AND W-CV2 = NS-SEQ-IRMO
                     AND W-CV3 = DA-UB-FORM-AS → DD030  else NB-PAYRE ← 2, DD040
              other neg → DD020
           CTR-DB ≤ 0 → NB-PAYRE ← 2, DD040   (97 / non-97 branches identical, L206-211)
  POS op:  CTR-MVT = CTR-DB − CTR-RECYC
           > 0 : 99 → NB-PAYRE ← 1, DD040 ; else DD030, CTR-DB +1
           = 0 : 99 → DD030, CTR-DB +1 (R2; old reject commented L227-228) ; else DD020, CTR-DB +1
           < 0 : CTR-RECYC −1 ; 99 → DD030 ; else DD020
  LECTURE (L242-248): READ INTO VMBZMEPI ; CLE-COUP ← key fields
F-TRAIT  (L162-167) CLOSE 4 files ; FINISH
```

DB2 flow is the same. D-COUP (seq 021700-027600) = SELECT-COUP + OPEN / first FETCH / `PERFORM RECH-EVTS UNTIL DZEVCPC1-EOC` / CLOSE. RECH-EVTS (seq 033400-034600) ends with `PERFORM 2200-FETCH`. TRAIT-COUP (seq 027800-032400) matches the legacy branch for branch (DSP-02, BIZ-FLOW-01) [OBS diff].

## 9. OCCURS / REDEFINES

No OCCURS. REDEFINES are only in VMBZMEPI (NR-ST-COUPON-R/-R1/-R2 and XX views; copybook 330001-1150001) and in the DATE-01 helper (DA-CCYYMMDD-R). None of these is referenced by the program logic. The legacy `W-CV REDEFINES` layout was decommissioned in R2 (L110-113). The record-side redefine NR-ID-STOCK-R3 (NR-PA-STOCK X(5)) explains why NR_IDSTOCK is CHAR(12) and not DECIMAL [INF]. The byte-copy split keeps alphanumeric content intact.

## 10. LR semantics

| LR request | Path (VMBTS09.txt L152-163) | Legacy statuses | DB2 |
|---|---|---|---|
| `OB-VMBCOUP-VMBEVCP` FIRST | `OBTAIN FIRST VMBCOUP WHERE CALCKEY = KY-COUPON OF LR` (0326 → VMBCOUP-NOT-FND); `IF VMBCOUP-VMBEVCP IS EMPTY` (0000 → NO-VMBEVCP-FND, 1601 NEXT); `OBTAIN EACH VMBEVCP WITHIN set` (0307 → NO-MORE-VMBEVCP) | LR-FOUND = owner + 1st member; the owner is also in storage on NO-VMBEVCP-FND [INF LRF] | SELECT-COUP (owner) + OPEN + FETCH (member) |
| `OB-VMBCOUP-VMBEVCP` NEXT | resumes at the iterative `OBTAIN EACH` [INF LRF] | LR-FOUND / NO-MORE-VMBEVCP | FETCH; 100 = NO-MORE |
| CALL PROCEDURES INFOCOMP/INFODCOM on both records (Schema-Listing L202-205, L276-279) | — | — | ignored (PROC-01) |

The `OBTAIN FIRST … WHERE CALCKEY` part of LRO-01 applies. LRO-02 (FETCH FIRST) does **not** apply, because every member is consumed. The pattern "owner by CALC, then full member walk feeding an aggregate" is new → **LRO-N130-1**. The inverse of LRO-N595-1 applies: on owner NOT-FND, LRF does not refresh the VMBCOUP area, so stale data stays (L-01).

## 12. Restart

There is no restart in the legacy program: no FFRECAB, no COMMIT, a RETRIEVAL run-unit [OBS L147, L167]. DB2 correctly omits the DZ01RSTV template. The team-wide template facts (V-01 rerun abend, LEN 1215/15, NB-READ positioning, CNT-01) do **not** apply. Rerun = full rerun from record 1, and the outputs are recreated (JCL out of scope). Both versions are idempotent.

### 15.2 New rules

| Rule | Statement | Guide |
|---|---|---|
| **LRO-N130-1** | **NEW.** Owner-CALC + full member walk (`OBTAIN FIRST/NEXT <LR> WHERE OB-<OWNER>-<MEMBER>`; path = OBTAIN CALC owner / IF set EMPTY / OBTAIN EACH member) consumed completely by the program → (a) singleton SELECT of the owner on all CALC columns; `<OWNER>-NOT-FND` → SQLCODE 100 with the legacy action (here non-fatal: skip the walk); (b) a member cursor on the FK columns with a FETCH loop; `NO-<MEMBER>-FND` and `NO-MORE-<MEMBER>` both → FETCH 100. Open the member cursor only when (a) returned 0, so the result does not depend on RI. | 04 |
| **ORD-N130-1** | **NEW.** When the member loop body is commutative (counters / sums only, no "first match", no STOP on a row), the set order is irrelevant: omit ORDER BY (or accept any direction) and fetch only the referenced columns. ORD-01 / Q-17 apply only to order-sensitive loops. | 04 |
| **DATE-N130-1** | **NEW.** Reverse date conversion (DB2 DATE → a legacy field that is compared or written) must reproduce the legacy **storage form** of that field. For 9(8) fields 0001-01-01 → zeros. For X(8) fields the migration rule decides (spaces vs zeros) and must be read from the data-migration spec, never assumed. Keep the 9999-12-31 → '99999999' branch (present here, missing in VMDZ1620). | 01 |
| **ERR-N130-1** | **NEW.** Every FETCH inside `PERFORM … UNTIL <EOC>` must, under `WHEN OTHER`, either abend (SQLERROR) or set EOC. A DISPLAY-only branch is an infinite-loop / wrong-result defect. Gate signature: `'ERROR WHILE FETCHING CURSOR'` followed by END-EVALUATE without SQLERROR. Current hits: VMDZ1015, VMDZ1130, VMDZ905T. | 04 |
