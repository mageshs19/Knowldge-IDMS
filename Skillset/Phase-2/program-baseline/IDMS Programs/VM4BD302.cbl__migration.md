# IDMS Programs/VM4BD302.cbl — IDMS to DB2 Migration Analysis

> **Purpose.** Knowledge base for one program pair: legacy VM4BD302 vs the manual DB2 conversion VMDZ4302. Written for a downstream conversion engine and its reviewers.
>
> **Evidence labels:** `[OBS]` observed in source, `[INF]` inferred, `[UNK]` needs a human answer. **NEW** marks a rule first proposed here (provisional ID `<CAT>-V4302-n`).
>
> **Line references:** legacy = **physical file lines** (`L`). Physical line = seq/100 exactly (L179 = 017900 `MOVE 'VM9BD302' TO PROGRAM-NAME`, L243 = 024300 `OBTAIN CALC VMBWCEF`, L319 = 031900; 337 lines, no inserts; verified by search). DB2 = cols 1-6 (`seq NNNNNN`, suffixes 03/04/05/…). The DB2 cols 1-6 **wrap** after seq 990003 (810 paragraph) to 000003; wrapped lines are cited by cols 73-80 as `seq* 0101xxxx`. Schema-Listing, VMBTS07, DCLGEN, copybook and mapping-CSV refs are physical lines.
>
> **Pairing.** Legacy header L7-8 "OPHALEN VAN EFFEKTEN MET EVENEMENTEN DIE TERUGBETAALD ZI[JN] 1 MAAND VOOR DE EINDVERVALDAG" = VMDZ4302 seq 000903-001003 "COLLECTION OF SECURITIES WITH REDEMPTION EVENTS … ONE MONTH PRIOR TO MATURITY". Also identical: DD010 40-byte input / DD005 90-byte output, INPUT-RECORD, VARIABLES names (SW-168, WS-DA-UE-MIN-1MAAND), CALL-VM9BC50T with key '2'. **Confidence: High.**

## 10. LR / DML semantics

- **Owner CALC + two nested set walks, direct DML.** Equivalent to LR path ALL-VMBEVEF-BY-VMBWCEF (VMBTS07.txt L137-155) but coded by hand; not-found owner → skip; empty VMBWCEF-VMBEFF (OBTAIN FIRST 0307) → no kasbon; empty VMBEFF-VMBEVEF → SW-168 stays '0' → no record. DB2 collapses each to SQLCODE 100 with the same effect (LRO-N130-1, LRO-V4302-1).
- **Currency.** OBTAIN VMBEVEF changes current of run-unit, area AR-VMBEFF1 and set VMBEFF-VMBEVEF, but **not** current of VMBWCEF-VMBEFF (VMBEVEF is not a member) → `OBTAIN NEXT VMBEFF WITHIN VMBWCEF-VMBEFF` (L277) needs no FIND CURRENT [INF IDMS currency rules] — contrast VM4BD300 area sweep (LRO-V4300-1). SQL cursors keep their own position.
- **Shared ERROR-STATUS.** Both `UNTIL ERROR-STATUS NOT = '0000'` loops test the last DML status; the inner 0307 is overwritten by the outer OBTAIN NEXT VMBEFF (L277) before the outer UNTIL test [OBS]. DB2 uses two flags (correct).
- **Redemption gate** [OBS L283-297]: 0168 AND CT-OPD 91 AND event date < run date AND event date ≥ (maturity − 1 month, same DD). Any one such event sets SW-168 → order-free.
- **Holder CI** (L300-315): same structure as VM4BD300 (ORD-V4300-1): first past 0060 sets CI only while LAATSTE-DA = 0; any later qualifying 0092 (transfer date > previous and < run date) overrides. Final CI order-free **except** ≥ 2 past 0060 without qualifying 0092, or equal 0092 dates (D-04, Q-110). Future 0060 is skipped; 0168 events never reach the 0092 branch. No early exit: legacy walks all events, DB2 fetches to EOC — equal.
- **Index set VMBWCEF-VMBEFF** (Schema-Listing L1300, L1327): member has index + OWNER pointer; sort key/order not printed. If sorted on KY-EFFECT, the legacy output within an issue is ascending kasbon key [INF] (Q-111).
