> **Purpose of this file.** Knowledge base for one program, written for a downstream AI or Python conversion engine. It records what the legacy program does, how the manual DB2 conversion (VMDZ1546) re-implemented it, and where the two differ.
>
> **Rule IDs** are defined in `../../generic/`. **NEW** marks a rule first seen here.
>
> **Evidence labels:** `[OBS]` observed, `[INF]` inferred, `[UNK]` needs a human answer.
>
> **Line references:** legacy `Lnnn` = sequence number / 100 (the physical file line is **+1**, e.g. `IF DATE-IND` = seq 011100 = file line 112); DB2 = COBOL sequence numbers (`seq NNNNNN`).

## 2. Business purpose and flow

### 2.1 Date initialisation (L111-125) — first program in this batch that tests `DATE-IND`

```
IF DATE-IND = '0'  → ACCEPT DATE-YMD FROM DATE (YYMMDD); century window: YY > 60 → 19 else 20
ELSE               → DATE-DMY8 ← DATE8-LS (PARM DDMMCCYY)
DATE-YMD8 ← DATE-DMY8 (MOVE CORR)
```

DB2 (seq 018810-020910) keeps this logic **exactly**, then derives DA-DD-MM-CCYY and WS-DA-DD-MM-CCYY. → **DATE-04 NEW**: keep the legacy `ACCEPT … FROM DATE` + window. Do not replace it with `FUNCTION CURRENT-DATE` (retain-legacy rule; the window is valid until 2060).

### 2.2 Dispatch (VERWERKING, L176-203)

| CT-LINE-TE | CO-STCIRC-OORD | Legacy | Event | LR | DB2 |
|---|---|---|---|---|---|
| 1 | 1 | REMISE-STORE | 0168 / 0221 | ST-VMBEVEF | 2100 (BEFF probe) → 2110 INSERT EVEF |
| 1 | other | REMISE-MODIFY | 0168 / 0221 | ALL-VMBEVEF-BY-VMBEFF + MO-VMBEVEF | 2200 SELECT (DESC) + UPDATE |
| other | 1 | ORDRE-STORE (+ FILL-COUPON) | 0060 / 0221 | ST-VMBWCEF-TO-VMBEVEF | 2300 WCEF probe → 2310 → 2320 (+ 2321) → 2330 |
| other | other | ORDRE-MODIFY | 0060 / 0221 | ALL-VMBEVEF-BY-VMBEFF + MO-VMBEVEF | 2400 SELECT (DESC) + UPDATE |

Legacy compares to numeric literal `1`; DB2 compares to `'1'`. These are equivalent for display digits [INF].

### 2.3 Field content per branch

- **REMISE-STORE:** VMBEFF key only; EVEF = PARM date, NR-ID-GOOD, DB-NR-CI. VMBEFF-NOT-FND / LR-ERROR → STOP01 'REMISE STORE' + status + whole input record + USERABEN.
- **ORDRE-STORE:** identical to VM1BD535 STORE-EFF (including `IF CO-COUP-FORM-AS NOT = SPACE → FILL-COUPON`), except TGDSV '0221'. VMBEFF-EXISTS / LR-ERROR → fatal.
- **Both MODIFY branches:** rebuild NR-ID-GOOD **and** DB-NR-CI, then MODIFY.

## 10. LR semantics

Same keywords and rules as VM1BD526 (ST-VMBEVEF → LRS-11; ALL-VMBEVEF-BY-VMBEFF → LRO-02 + ORD-01; MO-VMBEVEF → LRM-01) and VM1BD535 (ST-VMBWCEF-TO-VMBEVEF → LRS-10 + LRS-10-b fatal).

**Two events with the same TGDSV '0221' but different TEVPR (0168 vs 0060) can exist under one EFF.** The TEVPR predicate is therefore part of the "first event" WHERE clause. DB2 keeps both predicates [OBS seq 050400-050500, 092500-092600].

## 12. Restart

| Aspect | Legacy | DB2 |
|---|---|---|
| Key | 'VM1BDF546-A' + DATE-YMD8 (PARM or system date) | 'VMDZ1546' / 1 / WS-DA-DD-MM-CCYY (same origin) |
| Create | STORE at start, NB-DAY 7 | INSERT at start, NB_DAY 7, LEN 1215 |
| Positioning | READ VARYING … UNTIL EOF OR TELLER > NS-REC-FF-IN | NB-READ TIMES (no EOF guard) |
| Checkpoint / end | every 100 + end: ADD TELLER, MODIFY, COMMIT | 8300 (LEN 15, D-06) + COMMIT |

**RST-09 NEW:** when `DATE-IND = '0'` (system date), a restart on the next calendar day finds **no** restart row (different date key) and re-processes from record 1. Legacy and DB2 behave identically, so keep it as is. Flag it for operations: restart before midnight, or rerun with the PARM date.

## 15. Reusable rules and open questions

### 15.1 New rules

| Rule | Statement | Guide |
|---|---|---|
| **DATE-04** | `DATE-IND = '0'` → `ACCEPT … FROM DATE` + 2-digit century window: keep it verbatim. The resolved run date drives both the event date and the restart key. | 01, 02 |
| **PLAT-02** | `READY <area> USAGE-MODE …` lists (named areas, PROTECTED / SHARED) have no DB2 equivalent. Remove them; locking comes from the plan isolation. | 04 |
| **HLP-10** | When a shared date work field (DA-DD-MM-CCYY) is reused for record dates, keep a separate copy of the run date (WS-DA-DD-MM-CCYY) for the restart key and the event date. | 01 |
| **RST-09** | With a system-date restart key, a restart after midnight starts from record 1 (legacy parity). Document it; do not "fix" it. | 02 |
| **CNT-01** | The restart record counter must be at least as wide as the legacy FFRECAB NS-REC-FF-IN (9(7), Schema-Listing L48); NB-READ is 9(15). Never use 9(5) for WS-NB-INPUT-UPD-I. | 02 |
