## 2. Business flow

```
INIT : DATE-DMY8 ← DATE8-LS (PARM only; DATE-IND ignored) → DATE-YMD8
       restart FFRECAB 'VM1BDF555-A' + DATE-YMD8
LOOP : CO-STCIRC-OORD = '1' → STORE-EFF  else MOD-EVEF
       every 100 → checkpoint + COMMIT
END  : CLOSE, FINISH, STOP RUN        ← NO final checkpoint (see L-01)

STORE-EFF (L193-230)
  EVEF  ← PARM date, 0168/1816, NR-ID-GOOD, DB-NR-CI
  EFF key ← '1002' + NR-ST + NS-DB
  CT-OPD = 81                    → STORE-VMBEVEF          (ST-VMBEVEF; NOT-FND → STOP02 abend)
  CT-OPD = 82 AND SL-CO-DEV='BTE'→ STOP03 + currency, abend (no DB change)
  otherwise                      → STORE-VMBWCEF-TO-VMBEVEF
       WCEF/EFF keys, DA-UB, ISSUE 0, TPROD-EX '1003', AM-CND, AM-CN,
       NX-CPCRE ← NS-IDCP (UNCONDITIONAL), NX-CPAID 0, NX-CPFDU 0,
       AM-INTER ← input (UNCONDITIONAL)
       LR-ERROR / VMBEFF-EXISTS → STOP01 abend

MOD-EVEF (L297-328): first EVEF 0168/1816 under EFF → rebuild NR-ID-GOOD + DB-NR-CI → MODIFY
```

**Business-rule contrast (XPG-01):**

| Program | Coupon handling |
|---|---|
| VM1BD515 / VM1BD535 / VM1BD546 | FILL-COUPON with `NS-IDCP − 1` |
| **VM1BD555** | NX-CPCRE = NS-IDCP; CPAID = 0 and CPFDU = 0; **no condition on CO-COUP** |

VMDZ1555 reproduces the VM1BD555 rule exactly [OBS seq 045000-045700], so this is a correct non-clone.

## 12. Restart — legacy has NO end-of-job checkpoint

| Aspect | Legacy | DB2 |
|---|---|---|
| Key | 'VM1BDF555-A' + PARM date | 'VMDZ1555' / 1 / PARM date |
| Checkpoint | every 100 | every 100 **plus at EOF** with CO_ID_RS = '1' |
| End of job | **no** ADD TELLER / MODIFY FFRECAB. FINISH commits the data but NS-REC-FF-IN lags by up to 99 records [OBS L167-169]. | final checkpoint, complete flag |
| Rerun, same PARM date, after success | Positions at the last checkpoint and re-processes the last 1-99 records. A store record then gets VMBEFF-EXISTS (abend) on the chain path, or a **duplicate 0168/1816 event** on the 81 path [INF]. | 'PREVIOUS RUN COMPLETE' → USERABEN (V-01) |

- **L-01 (legacy defect):** no final checkpoint. DB2 fixes this through the shared template.
- **RST-10 NEW:** checkpoint and restart mechanics always follow the DB2 restart template (DZ01RSTV, final commit, completion flag). This applies even where the legacy omitted a step. The "retain legacy" rule (Q-25) applies to **business** logic, not to restart plumbing. Confirm via **Q-29**.

Other template defects: LEN 15 (D-02); no EOF guard during positioning (D-03).

## 15. Rules and open questions

### 15.1 New rules

| Rule | Statement | Guide |
|---|---|---|
| **RST-10** | Restart plumbing always follows the DB2 template (final checkpoint + completion flag), even when the legacy lacks it. Business logic still follows legacy. | 02 |
| **MSG-01** | `##&&<pgm>-STOPnn-…` literals may be scanned by operations monitoring. Keep the `##&&` prefix and STOP number. Replace the program name consistently (VM1BDnnn → VMDZnnnn). Never leave mixed names. | 03 |
| **DSP-02** | A multi-level dispatch (CO-STCIRC × CT-OPD × currency) must be reproduced branch-for-branch. A numeric literal compared with a PIC XX field becomes an alphanumeric literal ('81'). | 04 |
