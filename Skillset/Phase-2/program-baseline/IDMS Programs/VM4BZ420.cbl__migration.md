# IDMS Programs/VM4BZ420.cbl — IDMS to DB2 Migration Analysis

> **Purpose.** Knowledge base for one program pair: legacy VM4BZ420 vs the manual DB2 conversion VMDZ4425. Written for a downstream conversion engine and its reviewers.
>
> **Evidence labels:** `[OBS]` observed in source, `[INF]` inferred, `[UNK]` needs a human answer. **NEW** marks a rule first proposed here (provisional ID `<CAT>-W4420-n`).
>
> **Line references:** legacy = **physical file lines** (`L`), from a full numbered listing (245 lines). The sequence area steps by 10 with inserts and gaps (000001, 000041, 000381-000383, 000727-000729, 002301-002311, 002579-002593, 002771/2791/2841), so seq is never used (L149 = 002010 `OBTAIN FIRST VMBCOUP`, L188 = 002360 `FIND CURRENT`, L229 = 002950 `OBTAIN NEXT VMBEVCP`). DB2 = cols 1-6 (`seq NNNNNN`, step 100 with inserts 008610, 021010). Schema-Listing, VMBTS09, DCLGEN, copybook and mapping-CSV (`Modified - Field Mapping … V 1.0_Manual.csv`) refs are physical lines.
>
> **Pairing.** The VMDZ4425 header ("EXTRACT THE INPUT KASBONS DATA … DZCOUPTB(PARENT) → DZEVCPTB(CHILD)", seq 000900-001600) is Dhuri template boilerplate: the same first sentence is in VMDZ4200/4300/4302/4305/4420/7102 [OBS grep]; only the table line is specific, and it names the VMBCOUP/VMBEVCP tables. Body evidence: same FDs OUTFILE1/OUTFILE2 on DD010/DD020 with 35/80 bytes (L13-14, L30-44 = seq 002500-004700); `COPY VM4BZRP5 REPLACING ==:PREF:== BY ==WS==` and `TELLER-EVEN-MASK PIC -999`, each unique to this pair on both sides [OBS grep]; identical paragraph names (NIV-COUPON, B-PROG, E-COUPON, BEHANDELING, E-PROG); identical PARAM-DATONLY with DATE6-LS; identical date prologue, including the unusual `< 60` window; identical cause-code lists. **Confidence: High.** The number break (BZ420 → 4425, not 4421) is the only anomaly (Q-146).

## 10. LR / DML semantics

- **Area sweep with currency restore.** VMBEVCP lives in AR-VMBCOUP (Schema-Listing L275), so each OBTAIN VMBEVCP moves current-of-area to the event. `FIND CURRENT VMBCOUP` (L188) puts it back on the coupon before `OBTAIN NEXT … WITHIN AR-VMBCOUP` (L190) [INF IDMS currency]. In SQL the outer cursor keeps its own position → dropped (LRO-V4300-1). The unused LR equivalent is SWEEP-VMBCOUP-VMBEVCP (VMBTS09.txt L164-173), with NO-MORE-VMBCOUP / NO-VMBEVCP-FND / NO-MORE-VMBEVCP mapping to 720-100 / first 820-100 / 820-100.
- **Empty set.** OBTAIN FIRST member 0307 (L162-163) → BEHANDELING never runs → TELLER 0 → nothing. DB2: first FETCH 100 → TELLER 0 → nothing. Equal. Consequence: OUT-RECORD is written only after ≥1 BEHANDELING of the **same** coupon, so the 5 moved fields are always current.
- **Order independence** [INF L212-227]: the counter is a sum of ±1 terms; the 5 OUT-RECORD MOVEs depend only on the coupon. The result is the same for any member order (ORD-N130-1; ORD-V4300-1 class "order-free"). Only the outer order matters (D-01).
- **Dispatch.** 0 → none; 1 → DD010; OTHER (≥2, or ≤ −1) → DD020 with the signed mask. Events with an issue cause and NR-ID-GDIFC ≠ 0, and causes in neither list, are neutral [OBS L217-219].
- **Key reconstruction.** Legacy STRINGs the raw 24-byte CALC key, including its 6-byte FILLER (stored spaces, CSV L395). DB2 rebuilds it from 4 columns + FILLER VALUE SPACES. Byte-equal when NR_IDSTOCK holds the raw 12 IDMS bytes (KEY-W4420-1).
- CALL PROCEDURES INFOCOMP/INFODCOM (Schema-Listing L202-205) ignored (PROC-01).

### 15.2 New

| Rule | Statement | Guide |
|---|---|---|
| **KEY-W4420-1** **NEW** | `STRING`/`MOVE` of a whole IDMS CALC-key group to output → build a WS group with the exact legacy byte layout: every component in key order with its **legacy** PIC (CHAR column → X(n), never 9(n); DECIMAL → unsigned 9(n) DISPLAY), trailing key FILLER as VALUE per the CSV storage note ("Spaces in both TST and GTU"). Gate: sum of lengths = key length in Schema-Listing (here 24). | 04 |
| **HLP-W4420-1** **NEW** | Extends HLP-V4310-1 (c): a relocated INITIALIZE of an output WS record is equivalent only if every non-FILLER field is moved on every path that writes. List never-moved fields; they differ from legacy only on records written before the first legacy INITIALIZE (initial storage). INITIALIZE never touches FILLER, so FILLER bytes stay at initial storage in both. Either keep the legacy position or record the delta. | 04 |
| **CNT-W4420-1** **NEW** | CNT-01 (≥ 9(7)) applies to run/restart counters only. A business counter whose value is dispatched (`EVALUATE`) or edited to output (`-999` mask) keeps its legacy PIC and truncation behaviour (Q-25). | 04 |
| **DATE-W4420-1** **NEW** | A run-date prologue whose result is never referenced is copied verbatim (keeps the PARM/ACCEPT behaviour) and flagged dead. Do not add date validation or ESDATMAS. Gate: no reference to the computed date after the prologue. | 01 |
