# IDMS Programs/VM4BZ200.cbl — IDMS to DB2 Migration Analysis

> **Purpose.** Knowledge base for one program pair: legacy VM4BZ200 vs the manual DB2 conversion VMDZ4200. Written for a downstream conversion engine and its reviewers.
>
> **Evidence labels:** `[OBS]` observed in source, `[INF]` inferred, `[UNK]` needs a human answer. **NEW** marks a rule first proposed here (provisional ID `<CAT>-W4200-n`).
>
> **Line references:** legacy = **physical file lines** (`L`), 274 lines, verified with Select-String. Seq steps by 10 with re-used and inserted seqs (e.g. 000190/000200/000260 reused at L28-30, 000400 twice at L43-44, unnumbered L123-130, L173-189, L194-196), so seq is never used (L206 = 001730 `OBTAIN FIRST VMBFC`, L234 = 002010 `FIND CURRENT`, L261 = 001930 `MOVE VMBFC`). DB2 = cols 1-6 (`seq NNNNNN`, 563 physical lines). Schema-Listing, VMBTS09.txt, DCLGEN, copybook and mapping-CSV refs are physical lines.
>
> **Pairing.** Legacy L12 "EXTRACT DES FORMULAIRES C  A ARCHIVER" = VMDZ4200 seq 000900, identical text; it is the only hit on either side, and so is "NO DATUMBESTAND -STOP PGM" (L191 / seq 027200) [OBS grep]. Same FDs DARCH DD010 20 B (COPY VMBZ270I) / FORMC DD020 350 B, same paragraph names 000000/100000/300000/400000, same PARAM-DATONLY. **Confidence: High.**

## 2. Business flow (legacy, physical lines)

```
MAIN (L151-162)  PERFORM 100000; PERFORM 200000-AFLADEN UNTIL EOS-AREA; PERFORM 300000; STOP RUN
100000-BEGIN-PROGRAMMA (L164-211)
  run date: DATE-IND = '0' → ACCEPT WS-DA-YMD FROM DATE else DATE6-LS (DDMMYY) → WS-DA-CYMD   L173-183
            YY > 60 → 19 else 20; DISPLAY 'CHECK PARM DATE : ' WS-DA-CYMD (display only)    L184-189
  OPEN INPUT DARCH; READ AT END → DISPLAY 'NO DATUMBESTAND -STOP PGM', CLOSE, STOP RUN        L190-193
  DA-ARCH-YMD 9(8) → WS-DA-CYMD-18M (group) and WS-DA-COMP-18M 9(8) COMP-3; 2 DISPLAYs; CLOSE L194-197
  OPEN OUTPUT FORMC; PROGRAM-NAME ← 'VM4BZ200'; BIND RUN-UNIT, BIND VMBFC                     L199-202
  READY AR-VMBFRM4 RETRIEVAL; OBTAIN FIRST VMBFC WITHIN AR-VMBFRM4 ON DB-END-OF-SET → EOS 1  L204-208
200000-AFLADEN (L213-241)  -- one VMBFC, area (page) order
  IF (DA-CPTA ≠ '00000000' AND DA-CPTA < 18M) OR (DA-CR < COMP-18M AND DA-CPTA = '00000000') L223-230
     PERFORM 400000-SCHRYF                                                                   L231
  FIND CURRENT VMBFC; OBTAIN NEXT VMBFC WITHIN AR-VMBFRM4 ON DB-END-OF-SET → EOS 1 END-IF    L234-241
300000-EINDE-PROGRAMMA (L243-254)  FINISH; CLOSE FORMC
400000-SCHRYF (L258-267)  INITIALIZE NEW-REC-FORMC; C-REC-VMBFC ← VMBFC (raw 296 B);
                          C-DBKEY ← DBKEY (SUBSCHEMA-CTRL); WRITE FORMC-REC FROM NEW-REC-FORMC
```

**DB2 (VMDZ4200):** MAIN = 100000, `INITIALIZE DCLDZMBFCTV`, 710 OPEN / `720 FETCH UNTIL DZMBFCC1-EOC` / 730 CLOSE, 300000, STOP RUN (seq 023200-024200). 100000 = identical date prologue + DARCH (seq 025300-027900, minus WS-DA-COMP-18M), `600-GET-TIMESTAMP` (seq 026820), forward DATE-01 of the archive date into `WS-DB2-DA-CYMD-18M` X(10) 'DD.MM.CCYY' (seq 028100-028700), OPEN FORMC, PROGRAM-NAME ← CS-PROGRAM. The selection IF is **pushed into the cursor WHERE** (seq 020600-020900). 400000 = INITIALIZE + 500000 (39 column MOVEs into VMBFC of VMDZIBFC, 3 reverse date blocks, seq 031900-044200) + WRITE + `ADD 1 WS-NB-OUTPUT-COUNT`. 300000 = 2 DISPLAY totals + CLOSE [OBS].

## 10. LR / DML semantics

- **Area sweep without member walk.** No DML runs between OBTAIN FIRST/NEXT, so `FIND CURRENT VMBFC` (L234) re-establishes a currency that never moved; it only resets ERROR-STATUS [INF IDMS currency]. It is a leftover from the pre-97/05 VMBSIC + set-sweep design (L20-22, VMBTS09.txt L175-185). Dropping it is safe (LRO-V4300-1).
- **Filter pushdown.** The legacy fetches every VMBFC and filters in COBOL; DB2 filters in SQL. Equivalence per predicate [INF from L223-230, DCLGEN types]:
  - Branch 1: legacy alphanumeric group compare of X(8) YYYYMMDD vs WS-DA-CYMD-18M ≡ DATE compare for valid digit dates; `≠ '00000000'` ≡ `<> '01.01.0001'` if migration maps 00000000 → 0001-01-01 (DATE-N130-1). '99999999' ↔ 9999-12-31 excluded in both.
  - Branch 2: legacy numeric packed DA-CR < COMP-18M; DA-CR 0 → 0001-01-01 < date in both.
  - **Spaces in DA-CPTA** (legacy): `≠ '00000000'` true and X'40' < X'F0' → selected by branch 1. If migrated to 0001-01-01, DB2 selects only when DA_CR < archive date (D-04).
  - The archive date itself: same value in both compares (WS-DA-COMP-18M was only a packed copy).
- **Record image.** INFODCOM AFTER GET (Schema-Listing L1205) decompresses, so the legacy image is the full 296-byte layout; DB2 columns hold the same values (PROC-01). DLGTH 300 vs 296 listed bytes = compression control [INF].
- **DB-KEY.** The only area-sweep program that exports DBKEY [OBS grep `DBKEY` over VMDZ*: C-DBKEY only in VMDZ4200; FC-DBKEY in VMDZ4260 is declared but its DELETE uses NR_CIO/NR_ID/DA_CR, seq 041200-041500]. VM4BZ250 declares I-DB-KEY but never references it [OBS grep]. No in-workspace consumer of bytes 317-320 (Q-131).
