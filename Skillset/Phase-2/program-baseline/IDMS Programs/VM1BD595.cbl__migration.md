# IDMS Programs/VM1BD595.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base for the downstream conversion engine. Rule IDs refer to `../../generic/`; **NEW** marks a rule first seen here (provisional ID `<CAT>-N595-n`).
>
> - Evidence labels: [OBS] observed, [INF] inferred, [UNK] unknown.
> - **Legacy references are PHYSICAL file lines** (`Lnnn`). The file carries 6-digit sequence numbers and line 1 is seq 000010, so physical line = seq/100 + 1 (e.g. `FINISH` = seq 017100 = L172). DB2 references are `seq NNNNNN` (cols 1-6 of VMDZ1595).
> - No direct legacy sister: VM1BD595 is the only legacy program with VERWERK-41/43 + MOD-EVEF-NEW and event code 1818 used this way [OBS grep]. DB2 paragraph numbering is cloned from VMDZ1565/1575 (11100/11110/12100/12200), and the WCEF chain is cloned from VMDZ1555 (QUERYNO 656).

## 2. Business flow

```
INIT  L110-124 : DATE-IND='0' → ACCEPT DATE ; window  YY < 60 → 19 else 20   (INVERTED, L-02)
                 else DATE-DMY8 ← DATE8-LS (PARM) ; DATE-YMD8 ← DATE-DMY8
      L126-155 : PROGRAM-NAME ; OPEN ; BINDS ; READY ; FFRECAB 'VM1BDF595-A'+DATE-YMD8
                 found → skip NS-REC-FF-IN records (EOF-guarded, TELLER 9(5)) ; else STORE FFRECAB
LOOP  L176-197 : CT-OPD = '41' → VERWERK-41 else VERWERK-43 ; every 100 → MODIFY FFRECAB + COMMIT
END   L171-173 : CLOSE ; FINISH ; STOP RUN          ← NO final checkpoint (L-01)

VERWERK-41 L200-255  (MOVE SPACES TO VMBWCEF VMBEFF VMBEVEF)
  EVEF ← DATE-YMD8, 0168/1818, NR-ID-GOOD (HULP packed), DB-NR-CI ; EFF key '1002'+NR-ST-FORM-AS+NS-DB
  STCIRC = '1' → STORE-EVEF  (ST-VMBEVEF on OLD title; LR-ERROR / VMBEFF-NOT-FND → STOP02 abend)
  else         → MOD-EVEF    (first 0168/1818 under OLD EFF → NR-ID-GOOD → MO-VMBEVEF; else STOP03)
  EFF key ← NR-STNEW-GDIFRV + NS-DB-STOCK-GDIFRV ; WCEF/EFF ← 040SECU, 040IRMO, DA-UB ; ISSUE 0

  STCIRC = '1' OR CT-SL = '0' → STORE-EFF     (CPAID ← NS-CPAID-GDIFRV ; CPCRE = CPFDU ← NS-IDCP ;
                                               ST-VMBWCEF-TO-VMBEVEF ; LR-ERROR / VMBEFF-EXISTS → STOP01)
  else                        → MOD-EVEF-NEW  (first 0060/1818 under NEW EFF → GOOD → MODIFY ; else STOP03)

VERWERK-43 L257-276 : EVEF 0168/1818 ; EFF key = NEW title ; MOD-EVEF (no STCIRC test)
```

## 7. Cursor and transaction design

- No cursors. All reads are singleton SELECTs. 12100 uses `ORDER BY NR_ID_479EVEF DESC FETCH FIRST ROW ONLY` to emulate "first matching member in set order" (ORD-01, Q-17); the program-side search loop (L299-302) becomes WHERE predicates on TEVPR/TGDSV (LRO-02).
- Commit every 100 input records (seq 025200) plus once at EOF in F-PROG, with CO_ID_RS = '1' (RST-10). The restart UPDATE and business SQL share one unit of work (RST-LR-01).
- Restart table DZ01RSTV keyed `'VMDZ1595'` / phase 1 / DA_CR_RS = DA-DD-MM-CCYY. The structure is the VMDZ1565 variant: 800-RESTART-CONTROL → 700-SELECT, whose EVALUATE dispatches to 810 / 820 [OBS seq 066000-066800, 076200-077000].

No OCCURS. Legacy uses the input `-R` numeric redefines (NR-CIO-FORM-AS-R, DA-CREA-FORM-AS-R, CT-OPD/OPG-FORM-AS-R; HLP-04). DB2 adds the HLP-06 split helpers and DA-CCYYMMDD-R. ### 15.2 New rules

| Rule | Statement | Guide |
|---|---|---|
| **LRO-N595-1** **NEW** | After an LRF OBTAIN returns LR-FOUND, every element record the path obtained (owner **and** member) is overwritten in program storage. If the program later STOREs a record built in those same areas without re-initialising them, the fields it does not move carry the obtained DB values. The DB2 conversion must SELECT those columns (not only the surrogate PK) and carry them into the INSERT host variables, or the gap must be signed off. Complements HLP-09. | 04 |
| **HLP-N595-1** **NEW** | Legacy `MOVE SPACES TO <record>` followed by a STORE that never fills its COMP-3 fields writes X'40' bytes (invalid packed). DB2 cannot store this, so the INITIALIZE result (0) is accepted. Log it as a legacy defect; never emulate it. | 04 |
