## 2. Business flow

```
INIT : DATE-DMY8 ← DATE8-LS (PARM only; DATE-IND ignored) → DATE-YMD8            [L97-100]
       PROGRAM-NAME 'VM1BD567' ; OPEN ; BINDS ; READY UPDATE                       [L102-105]
       FFRECAB 'VM1BDF567-A' + DATE-YMD8 : OBTAIN CALC                             [L111-115]
         found     → skip NS-REC-FF-IN records (VARYING CTR-REC, EOF-guarded)      [L117-120]
         not found → STORE FFRECAB (NB-DAY 7, counters 0)                          [L121-129]
       IF NOT EOF → READ first record                                              [L132-134]
LOOP : VERWERKING until EOF                                                        [L136]
       VMBFAR ← SPACES ; key = 1815 + CIO + DA-CREA + NR-ID + OPG + OPD            [L149-155]
       OBTAIN CALC VMBFAR   (no ON clause → AUTOSTATUS: 0326 = abort)              [L156]
       DA-INFSD-GDIFAR ← DATE-YMD8 ; MODIFY VMBFAR                                 [L157-158]
       IF CTR-REC > 99 → checkpoint FFRECAB + COMMIT  ← CTR-REC NEVER INCREMENTED (L-01) [L161-167]
       READ next                                                                   [L170]
END  : FIND CURRENT FFRECAB ; ADD CTR-REC ; MODIFY ; CLOSE ; FINISH ; STOP RUN     [L138-144]
```

DB2: same per-record logic as one searched UPDATE (1000-VERWERKING seq 019200 → 1100-UPDATE-VMBFAR seq 042600), commit every 100 + EOF via the DZ01RSTV template.

## 7. Cursor & transaction design

- **No cursors, no FETCH, no ORDER BY / FETCH FIRST.** One searched UPDATE per input record (LRM-01-b conditions hold: CALC DUP NOT ALLOWED [OBS Schema-Listing L583]; nothing read between OBTAIN and MODIFY; NOT-FND fatal).
- Restart SQL: SELECT QUERYNO 376, UPDATE QUERYNO 398, INSERT (no QUERYNO).
- **Commit frequency.** Legacy: in practice **one unit of work until FINISH** (L-01). DB2: every 100 records (WS-TELLER incremented on each successful read; check after processing) + EOF → RST-10 governs.
- Paragraph scoping: `MOVE 0 TO WS-TELLER` seq 028300 follows the period at seq 028100 but still belongs to 700-RESTART-CONTROL and executes [OBS]. Unlike VMDZ1257, no `SET VMDZ205I-NOT-EOF` follows; instead `*SET VMDZ205I-EOF TO TRUE` is commented (seq 028400).
- Template variant: paragraphs named 700/710/720 (also used by VMDZ1583/1593/1620/1623/4260/4306/7240 [OBS grep]); D-line texts still say '810-…' / '820-…' (seq 028900, 030800).

## 10. LR semantics

**No LR.** VM1BD567 uses plain DML against subschema VMBTS06 (the same subschema serves LR VMBTL06-R01 in VM1BD250/252; `USAGE IS MIXED` permits both). Consequences for the engine:
- No path statuses (LR-FOUND / LR-NOT-FOUND / LR-ERROR) to map; error mapping comes from the **ON clauses** and AUTOSTATUS: no ON clause = every non-0000 status is fatal → only SQLCODE 0 is success (**DML-N567-1**).
- `OBTAIN CALC` + `MODIFY` on the same record with nothing read in between = LRM-01-b (fused UPDATE), same as the LR case in VM1BD257.
- VMBFAR record procedures INFOCOMP (BEFORE STORE / MODIFY) and INFODCOM (AFTER GET) [OBS Schema-Listing L585-588] → PROC-01 (ignored).
- Set VMBSIAR-VMBFAR membership is not affected by MODIFY; FK columns NR_CIOFMAS_479SIAR / NR_IDFMAS_479SIAR are not in the SET list (correct).

### 15.2 New rules

| Rule | Statement | Guide |
|---|---|---|
| **DML-N567-1** **NEW** | Direct (non-LR) DML under `BATCH-AUTOSTATUS`: a verb **without** an ON clause is fatal on any non-0000 status → emit `WHEN 0` success, everything else (incl. +100) `PERFORM SQLERROR`. `OBTAIN CALC <rec>` + `MODIFY <rec>` with nothing read in between → fused searched UPDATE on all CALC-key columns (LRM-01-b applies to direct DML as well as LR paths). | 04 |
| **RST-N567-1** **NEW** | Detect legacy checkpoint counters that are tested/added but never incremented (dead commit block). Record as L-defect; do not reproduce. Generate the template counter (increment on successful read, commit when > 99, final commit at EOF) per RST-10. | 02 |
| **KEY-N567-1** **NEW** | A CALC-key type code moved through a numeric REDEFINES (`MOVE 1815 TO CT-RK-TGOOD 9(4)` over X(4)) maps to the CHAR column as the alphanumeric literal `'1815'`; trailing key FILLER is dropped from the WHERE. Verify the writer program uses the same literal. | 04 |
