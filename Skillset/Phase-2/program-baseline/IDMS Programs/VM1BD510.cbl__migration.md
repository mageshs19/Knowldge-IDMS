# IDMS Programs/VM1BD510.cbl — IDMS to DB2 Migration Analysis

> **Purpose of this file.** Knowledge base for one program, written for a downstream AI or Python conversion engine. It records what the legacy program does, how the manual DB2 conversion (VMDZ1510) re-implemented it, and where the two differ.
>
> **Rule IDs** are defined in `../../generic/`. **NEW** marks a rule first seen here.
>
> **Evidence labels:** `[OBS]` observed, `[INF]` inferred, `[UNK]` needs a human answer.
>
> **Line references:** legacy = file line numbers; DB2 = COBOL sequence numbers (`seq NNNNNN`). In this pair the body sequence numbers are identical in both files; DB2 file line = legacy line + 7.

## 2. Business purpose and flow

**Remarks (header):** "BCI : VALIDATION DES SOUSCRIPTIONS". The program validates subscriptions to cash bonds (BCI / SLIK). It runs a battery of business controls on each subscription. It then routes the subscription to accounting, provisions, stock (effects) and coupon files, or writes it to the anomaly file.

### 2.1 Files (L202-207, L219-270)

| DD | FD | Direction | Record written from | Content |
|---|---|---|---|---|
| DD005 | OPERATIE | Input | read INTO `VMBD205I` → DB2 `VMDZ205I` | Subscription operations (on-line validated input) |
| DD010 | EFFECTEN | Output | `VMBD205I` | Accepted bearer subscriptions → stock creation (consumed by VM1BD515 — "STORE-EFF" chain) [INF] |
| DD030 | ANOMALIE | Output | `VMBD205I` | One record per control that fails (ERR-CODE + CO-SEVERITE) |
| DD040 | BOEKHOUD | Output | `VMBD205I` | Accepted subscriptions → accounting, with the **original on-line** ERR-CODE/SEVERITE restored |
| DD050 | COUPONS | Output | `VMBD205I` | Bearer subscriptions with physical coupons (`BC50O-CO-PHYS-COUP = '0' or '1'`) → VM1BD255 [INF] |
| DD060 | PROVISIE | Output | `VMBD510B` → `VMDZ510B` | Min/max provisioning record: NR-ST + NB-ST-USED = 1 |

### 2.2 Main line (L459-550)

```
CALL ESENVIRO (TSO/CICS switch)
Run date: PARM DATE-IND='0' → ACCEPT DATE (YYMMDD, window >60 → 19xx); else PARM DATE8-LS (DDMMCCYY)
OPEN files; READ first OPERATIE  — AT END: CLOSE all, STOP RUN   (no DB call at all on empty input)
CALL VM9BD05T 'OPEN ' (EF5-NM-FUNCTION='CONSULTT', EF1-DA-PARM = DATE-YMD8) — CO-RETURN ≠ '0000' → USERABEN
PERFORM HOOFDVERWERKING UNTIL SW-EOF = 'Y'
CALL VM9BD05T 'CLOSE' — CO-RETURN ≠ '0000' → USERABEN
CLOSE files; STOP RUN
```

### 2.3 HOOFDVERWERKING (L553-575)

```
SW-BYPASS-CTRL-TC = 'Y' if NR-DS-FORM-AS ≠ 0 AND CO-STCCUST-OORD ≠ '1' (security-dossier, not customer-validated)
IF bypass = 'N' → RECH-TC          (tariffs & conditions via GE9TG002)
*  PERFORM RECH-TC-THEOR           (COMMENTED OUT — VM9BD02T path is dead code, see §13 D-04)
RECH-COND-VENTE-GEN                (general sales conditions via VM9BCKX2, cached on DA-CREA)
TRAIT-SLIK
READ next
```

### 2.4 TRAIT-SLIK — routing decision (L579-615)

| Condition | Controls performed | Accepted when | Outputs when accepted |
|---|---|---|---|
| `NR-DS-FORM-AS-P1 = '000'` (bearer / "porteur") | CONTR-PORTEUR-SLIK with CO-SEVERITE '1' | `CO-SEVERITE ≠ '2'` after controls | BOEKHOUD, PROVISIE, EFFECTEN, COUPONS (if physical coupons) |
| Else, `NR-REFORD-OORD(1:2)='AS'` and `(5:2)='15'` (ASTERA) | **none** (CONTINUE) | `ERR-CODE(1:3) = '000'` | BOEKHOUD only |
| Else (security dossier, "DT") | CONTR-EFFDOS-SLIK | `ERR-CODE(1:3) = '000'` | BOEKHOUD only |

Before routing, the on-line ERR-CODE / CO-SEVERITE / TE-ERROR-OORD are saved (`IN-*`). WRITE-BOEKHOUD-REC restores them, so accounting receives the **on-line** warning and not the batch control result (L1600-1605).

## 7. Cursor and transaction flow

| Aspect | Legacy | DB2 |
|---|---|---|
| Cursors in caller | None | None |
| Run-unit / thread | Opened by VM9BD05T OPEN (BIND RUN-UNIT), closed by CLOSE (FINISH) | DB2 thread is opened by the DSN attach at program start; OPEN/CLOSE calls are no-ops |
| Commit | None (retrieval only) | None (read-only; implicit at thread end) |
| Lock / isolation | READY ... RETRIEVAL (no locks held) | Package isolation of VMDZ905T [UNK] — recommend `ISOLATION(CS)` or `UR` per site standard (Q-23) |
| Cursor inside callee | `OBTAIN FIRST/NEXT ... WHERE ALL-VMBEVEF-BY-VMBEFF` | `DZEVEFC1` OPEN / FETCH / CLOSE per READ call (seq 069300-074100) |

Callee note X-01 (for the VM9BD05T report): in `2200-FETCH-DZEVEFC1`, `WHEN OTHER` only DISPLAYs. It does not call SQLERROR and does not set EOC (seq 073100-073200). A negative SQLCODE on FETCH can therefore loop RECH-EVTS forever (`PERFORM RECH-EVTS UNTIL DZEVEFC1-EOC`, seq 057000). The caller cannot detect this.

## 13. Defects and variants

## 14. Validation scenarios

Primary acceptance criterion: on the same input file and the same database snapshot (IDMS unload → DB2 load), the **five output files must be byte-identical** (EFFECTEN, ANOMALIE, BOEKHOUD, COUPONS, PROVISIE), including record order.

| ID | Scenario | Expected (legacy = DB2) |
|---|---|---|
| V-01 | Empty OPERATIE | 5 empty outputs, RC 0, no DB call |

## 15. Reusable rules and open questions

### 15.1 Rules confirmed or introduced

| Rule | Status | Statement |
|---|---|---|
| **PLAT-01-c** | **NEW** | A program with `IDMS-CONTROL SECTION` / `PROTOCOL` / `IDMS-RECORDS` but **no SCHEMA SECTION and no DML**: delete those three declaratives. Add nothing (no SQLCA, no SQLERROR include, no DCLGEN). Keep `CBL NOSQL`. |
| **CALL-01** | **NEW** | A called subprogram that itself issues IDMS DML is replaced by its DB2 counterpart. Change the module-name constant (data-name **and** VALUE), every `CALL` that uses it, and the DISPLAY texts. Mapping seen here: `VM9BD05T → VMDZ905T`, `VM9BD02T → VMDZ902T` (pattern `VM9BDnnT → VMDZ9nnT`). |
| **CALL-02** | **NEW** | Called modules without IDMS DML (DB2 already, e.g. VM9BCKX2; platform GE*/ES*; VM9SU35T) keep their names. The engine needs an **authoritative list** of IDMS-accessing modules; do not guess from the prefix (Q-24 for VM9BC50T/52T). |
| **CALL-03** | **NEW** | The interface contract of a renamed module (return-code fields and values) must be identical. The caller's error-handling code is **not** changed. Contract changes in the callee (e.g. D-02) are callee defects. |
| **CPY-01** | **NEW** | Copybooks shared with converted modules are renamed `VMBDxxxx → VMDZxxxx` (`VMBD205I→VMDZ205I`, `VMBD510B→VMDZ510B`, `VMBD05→VMDZ05`, `VMBD02→VMDZ02`). Rename the COPY statement, every `OF <01-name>` qualifier, and every direct use of the 01-name (`MOVE SPACES TO`, `WRITE ... FROM`, `READ ... INTO`, `INITIALIZE`, `CALL ... USING`). Layout must stay byte-identical. |
| **NAME-03** | **NEW** | Every literal equal to the old program-ID (`'VM1BD510'`) becomes the new program-ID (`'VMDZ1510'`). This covers interface caller-name fields and DISPLAY texts, not only PROGRAM-ID. |
| **ERR-04** | **NEW** | Preserve the legacy caller-side error logic verbatim, even when it is visibly defective (D-01). Raise it as a defect for business sign-off; do not "fix" it during conversion. |
| **RST-08** | **NEW** | No DZ01RSTV restart template for programs without database updates. |
| **HLP-08** | **NEW** | No SQL helpers (SQLCA, SQLERRWS, DCLGEN, date/timestamp helpers) in a program without SQL. |
| DATE-01, AUD-01/02, LRS-*, LRO-*, LRM-* | Not applicable | No DB2 columns written or read by the caller |
