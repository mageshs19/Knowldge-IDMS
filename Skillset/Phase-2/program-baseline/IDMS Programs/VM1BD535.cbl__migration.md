# IDMS Programs/VM1BD535.cbl — IDMS to DB2 Migration Analysis

> **Purpose of this file.** Knowledge base for one program, written for a downstream AI or Python conversion engine. It records what the legacy program does, how the manual DB2 conversion (VMDZ1535) re-implemented it, and where the two differ.
>
> **Rule IDs** are defined in `../../generic/`. **NEW** marks a rule first seen here.
>
> **Evidence labels:** `[OBS]` observed, `[INF]` inferred, `[UNK]` needs a human answer.
>
> **Line references:** legacy = file line numbers; DB2 = COBOL sequence numbers (`seq NNNNNN`).

## 2. Business purpose and flow

```
VMBWCEF  (issue header: security code + IRMO seq + maturity date)        DZWCEFTV  CALC, DUP NOT ALLOWED (Schema-Listing L1296)
   └─ VMBEFF   (stock line: '1002' + stock id 12 + check digit + DB seq) DZBEFFTV  CALC KY-EFFECT, DUP NOT ALLOWED (L1319)
         └─ VMBEVEF (event 0060, good type 0220, NR-ID-GOOD = form key) DZEVEFTV  VIA VMBEFF-VMBEVEF (L1383)
```

### 2.1 Main line (L109-112) and dispatch (TRAIT, L150-164)

| `CO-STCIRC-OORD` | Legacy | DB2 |
|---|---|---|
| `'1'` | STORE-EFF | 1100-INSERT-EFF → 1110-SELECT-DZWCEFTV → (110-INSERT-DZWCEFTV) → 120-INSERT-DZBEFFTV → 130-INSERT-DZEVEFTV |
| other | MOD-EVEF | 1200-UPDATE-EVEF → 1210-SELECT-EVEF → 1220-UPDATE-EVEF |

### 2.2 STORE-EFF (L166-215) and FILL-COUPON (L217-223)

```
MOVE SPACES TO VMBWCEF, VMBEFF, VMBEVEF
WCEF + EFF copy : CO-IDPRKB-STOCK ← NR-ID-040SECU, NS-IRMO-STOCK ← NS-SEQ-040IRMO, DA-UBSECIS-STOCK ← DA-UB-FORM-AS
EFF             : NR-ID-ISSUE / NR-CD-ISSUE 0, CT-RK-TPROD '1002', CT-RK-TPROD-EX '1003',
                  AM-INTER-STOCK = NX-CPCRE = NX-CPAID = NX-CPFDU = 0,
                  NR-ID-STOCK-CD ← NR-ST-FORM-AS, NS-DB-STOCK ← NS-DB-STOCK-FORM-AS,
                  AM-CND-STOCK ← AM-CND-FORM-AS, AM-CN-STOCK ← AM-CNS-FORM-AS
EVEF            : DA-CR-EVENT-PROD ← PARM date, CT-RK-TEVPR '0060', CT-RK-TGDSV '0220',
                  NR-ID-GOOD ← HULP-NR-ID-GOOD, DB-NR-CI ← NR-CIO-FORM-AS
IF CO-COUP-FORM-AS NOT = SPACE        (' ' = no coupons, '0' = coupons with signature, '1' = physical coupons)
   FILL-COUPON: AM-INTER-STOCK ← AM-INTER-FORM-AS, NX-CPCRE ← NS-IDCP-FORM-AS,
                SUBTRACT 1 FROM NS-IDCP-FORM-AS GIVING NX-CPAID-STOCK (PIC 999 unsigned), NX-CPFDU ← NS-IDCP-FORM-AS
STORE VMBTL07-R01 WHERE ST-VMBWCEF-TO-VMBEVEF
   path: OBTAIN WCEF CALC; 0326 → STORE WCEF | STORE VMBEFF (1205 → RETURN VMBEFF-EXISTS) | STORE VMBEVEF
   LR-ERROR or VMBEFF-EXISTS → DISPLAY STOP01 + LR-STATUS, CALL USERABEN
```

### 2.3 MOD-EVEF (L225-256)

```
set KY-EFFECT; OBTAIN FIRST VMBTL07-R01 WHERE ALL-VMBEVEF-BY-VMBEFF AND CT-RK-TEVPR = '0060' AND CT-RK-TGDSV = '0220'
   not LR-FOUND → DISPLAY 'RECH EVTS RETRAIT' + key + status, USERABEN
NR-ID-GOOD ← rebuilt; DB-NR-CI ← NR-CIO-FORM-AS          ← two fields change (VM1BD526 changes only NR-ID-GOOD)
MODIFY VMBTL07-R01 WHERE MO-VMBEVEF → not LR-FOUND → DISPLAY 'UPDATE CLÉ FORM', USERABEN
```

**Business meaning [INF]:** a '1' input creates a new security position for a withdrawal ("retrait"). A duplicate stock line is an error. A correction input rewrites the form key and the CI number of the first 0060/0220 event.

## 7. Cursor / transaction design

- No cursor. LR walk → singleton SELECT (LRO-02). Owner probe of WCEF → singleton by full CALC key (no -811 risk: DUP NOT ALLOWED).
- STORE chain (LRS-10 variant **fatal-EXISTS**):
  - WCEF: SELECT → 100 → INSERT.
  - BEFF: INSERT, where **-803 = fatal** (STOP02 + SQLERROR). This matches the legacy `VMBEFF-EXISTS → USERABEN`.
  - EVEF: INSERT.
- **LRS-10-b NEW:** the treatment of `-803` on the middle record follows the legacy handling of the `*-EXISTS` status: continue (VM1BD515) or abend (VM1BD535). Always read the status test after the STORE.
- Commit every 100 records and at EOF.

## 15. Reusable rules and open questions

### 15.1 New rules

| Rule | Statement | Guide |
|---|---|---|
| **XPG-01** | Never reuse the DB2 conversion of a sister program (same subschema, same LR) without re-diffing **every MOVE and IF** of the legacy paragraph. Sister programs differ in conditions (CO-COUP here), constants (0029 / 0220 / 0219), `*-EXISTS` handling, and the MODIFY field list. | all |
| **LRS-10-b** | In a STORE chain, `-803` on a middle record follows the legacy status test: `*-EXISTS` handled as continue → treat -803 as success and continue; `*-EXISTS` in the abend list → -803 is fatal. | 04 |
| **ARI-01** | A legacy `SUBTRACT/COMPUTE … GIVING <unsigned field>` silently drops the sign. To keep legacy results, compute into an unsigned helper of the same picture before moving to a signed DCLGEN host variable. | all |
