# IDMS Programs/VM1BZ250.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base. Rule IDs refer to `../../generic/` and earlier program reports; **NEW** marks a rule first seen here (provisional ID `<CAT>-Z250-n`).
>
> - Evidence labels: [OBS] observed, [INF] inferred, [UNK] unknown.
> - Legacy `Lnnn` = **physical file line**, verified with Select-String. This file has **no inserted lines**: L1 = seq 000010, then seq steps by 100, so physical = seq/100 + 1 (e.g. `OBTAIN FIRST` seq 021700 = L218, `OBTAIN NEXT` seq 025700 = L258, `CALL USERABEN` seq 030000 = L301). Do not assume this for other BZ files (BZ130/140 step by 10).
> - DB2 references are `seq NNNNNN` from cols 1-6 of VMDZ1251. Seq 018100 is duplicated (physical L182-183, cols 73-80 00018100/00018110). Physical = seq/100 up to L182, seq/100 + 1 after it (QUERYNO 331 seq 035000 = L351).
> - Schema-Listing, VMBTS09.txt, DCLGEN and CSV references are physical lines of those files.

## 2. Business flow

```
000-STUUR (L147-160)  100-INITIALISATIE ; 200 UNTIL SWEOF1 = 1 ; CLOSE 3 files ; FINISH ; STOP RUN
100 (L162-187)  PROGRAM-NAME, BIND ×3, READY RETRIEVAL                                    [L167-171]

     DATE-Y < 60 → DATE-Y1 20 (default 19)                                                [L177]
     OPEN ; READ INFIL1 INTO VMBD205I ; READ INFIL2 INTO VMBZMEP (EOF → NR-ST 9999999999999) [L181-186]
200 (L195-205)  IF NR-DS-FORM-AS-R = SPACES | '000000000000'
                   TELLER ← NS-IDCP-FORM-AS ; PERFORM VERWERK UNTIL TELLER > 999          [L197-200]
                READ INFIL1                                                               [L202]
VERWERK (L210-249)
  TELLER1 ← 0 ; KY-COUPON ← SPACES ; key ← NR-ST-FORM-AS, NS-DB-STOCK-FORM-AS, TELLER    [L212-217]
  OBTAIN FIRST VMBTL09-R01 WHERE OB-VMBCOUP-VMBEVCP ; LR-ERROR → STOP1                    [L218-220]
  LECT-INFIL2 UNTIL MEP+ key ≥ (NR-ST, NS-DB, TELLER)  (3-level merge)                    [L221-230]
  MEP+ key = current coupon → AM-IND(VMBZMEPI) ← AM-IND(VMBZMEP) ; TELLER1 ← 1             [L232-237]
  (VMBCOUP-NOT-FND | NO-VMBEVCP-FND) AND TELLER1 = 0 → TELLER ← 9999 (ends rank loop)    [L238-241]
  LR-FOUND → AM-IND(VMBZMEPI) ← AM-INTGR-COUPON ; VERWERK1 UNTIL NO-MORE-VMBEVCP          [L242-245]
  TELLER1 ≠ 0 → UITSCHRIJF ; ADD 1 TO TELLER                                              [L246-249]
VERWERK1 (L251-258)  cause ∈ {51,65,72,82,92,98,99}: NR-ID-GDIFC ≠ 0 → nothing, else +1 ; other cause → −1
                     OBTAIN NEXT VMBTL09-R01 WHERE OB-VMBCOUP-VMBEVCP
UITSCHRIJF-00 (L263-290)  CO-STCIRC-OORD '0'|'9' → GO EX ; fill 15 MEPI fields, SIGN-OPER '2' ; WRITE
```

### 15.2 New rules

| Rule | Statement | Guide |
|---|---|---|
| **LRS-Z250-1** | **NEW.** Classify every legacy LR-STATUS test of an owner→member path as **member-level** (`= 'LR-FOUND'`: owner and ≥ 1 member) or **owner-level** (`NOT = '<OWNER>-NOT-FND'`: owner found, set may be empty). Member-level actions go under the first FETCH `SQLCODE = 0`; owner-level actions go under the owner SELECT `SQLCODE = 0`. VMDZ1251 is right (member-level, seq 042000); the twin VMDZ1263 uses the same placement while legacy VM1BZ260 L275 is owner-level → verify in the 260 analysis. | 04 |
| **DSP-Z250-1** | **NEW.** Never merge independent legacy IF sentences on LR-STATUS into one IF/ELSE: ELSE = NOT(first predicate), which is wider than the second legacy predicate (third states: owner missing + orphan members, owner + empty set). Emit one IF per legacy sentence with the exact DB2 equivalent predicate (`SW-FOUND = 1 AND COUNT > 0` for LR-FOUND). | 04 |
| **ERR-Z250-1** | **NEW.** A legacy STOP paragraph reached only by `IF LR-STATUS = 'LR-ERROR'` after an LRF call maps to the `WHEN OTHER` of the replacing SQL statements: DISPLAY the legacy STOP texts (program name substituted, MSG-N620-1) and the SQLCODE, then `PERFORM SQLERROR` (ERR-01). Do not drop the texts even if the STOP was pre-empted by BATCH-AUTOSTATUS. | 04 |
