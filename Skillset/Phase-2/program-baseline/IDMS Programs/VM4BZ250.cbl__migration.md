# IDMS Programs/VM4BZ250.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base. Rule IDs refer to `../../generic/` and earlier program reports; **NEW** marks a rule first seen here (provisional ID `<CAT>-W4250-n`).
>
> - Evidence labels: [OBS] observed, [INF] inferred, [UNK] unknown.
> - Legacy references `Lnnn` = **physical file lines**. Here L1 = seq 000100 and there are no inserted lines, so **L = seq/100** (verified by search: L65 = 006500 I-VMBFC, L96 = 009600 COPY IDMS, L364/L444 = MOVE I-VMBFC).
> - DB2 references = `seq NNNNNN` from cols 1-6 of VMDZ4250. Cols 73-80 end in `01` (unchanged line) or `03` (line changed by the migration) [OBS].
>
> Second program of the **no-DML class** after VM4BD230 (closest sister report). Both versions have 474 lines. A full diff of cols 7-72 shows 12 lines removed and 12 lines added; nothing else differs [OBS].

## 2. Business flow

```
MAIN      : PERFORM B-PROG ; IF SW-FIN = ZEROES PERFORM VERWERKING. ; PERFORM E-PROG          [L349-352]
VERWERKING: PERFORM SCHRIJVEN UNTIL SW-FIN = 1 ; PERFORM E-SCHRIJVEN                           [L354-356]
B-PROG    : OPEN INPUT INFILE OUTPUT PRINTFILE ; PERFORM ACCEPT-DATE                          [L358-361]
            (DB2: PERFORM E-INITIALIZATION  seq 036101-036102)
            READ INFILE AT END MOVE 1 TO SW-FIN ; MOVE I-VMBFC TO VMBFC (unconditional)       [L363-364]
            PERFORM TITEL  (header page printed even when the file is empty)                 [L366]
SCHRIJVEN : line 11 (keys/ids/dates/codes)  L370-395  ; line 12 (6 amounts) L397-402 (+ dup L404)
            line 13: IF CO-DEV-GDIFC='BTE' → 'EUR' ELSE CO-DEV ; FX/type/status/pay date     [L406-423]
            line 14: NR-USER, TE-REF, NR-ID-040SECU, NR-SEQ-040IRMO, DA-UBSEC-040ISSU→KDAT  [L425-429]
            IF CT-LINE > 52 → PERFORM TITEL                                                   [L434-435]
            WRITE LA11, LA12, LA13, LA14 AFTER 1 ; ADD 4 TO CT-LINE                           [L437-441]
            (DB2: PERFORM E-INITIALIZATION  seq 044210-044220)
            READ INFILE AT END MOVE 1 TO SW-FIN ; MOVE I-VMBFC TO VMBFC                       [L443-444]
E-SCHRIJVEN: WRITE LA-END AFTER 3                                                             [L446-447]
TITEL     : LA01 AFTER S-PAGE, LA03 AFTER 2, LA04..LA10 AFTER 1 ; MOVE 10 TO CT-LINE         [L449-459]
ACCEPT-DATE: DATE-IND='0' → ACCEPT DATE6R-WS FROM DATE (YYMMDD), MOVE CORR → DATE4
             else DATE6-LS → DATE6 (DDMMYY), MOVE CORR → DATE4 ; DATE4 'MM/YY' → LA01-DATE   [L462-468]
E-PROG    : CLOSE INFILE PRINTFILE ; STOP RUN                                                 [L470-473]
(DB2 only) E-INITIALIZATION: INITIALIZE VMBFC                         seq 047310-047322 (after E-PROG)
```

**Pagination** [OBS + INF arithmetic]: TITEL uses physical lines 1-10. Each record adds 4 lines. The break test runs before each record, so there are **11 records per page** (CT-LINE 10→54). LA-END can reach line 57. DB2 has the same logic.

## 7. Cursor & transaction

N/A. There is no run unit in legacy (no BIND, so IDMS is never entered despite PROTOCOL), and VMDZ4250 has no SQL, so there are no cursors, COMMIT or thread. Read order = file order, so ORD-01 / Q-17 do not apply. The DB2 commit/restart template (DZ01RSTV) is correctly **not** injected [OBS]. Plan/bind: none is needed (JCL out of scope, Q-22).

## 12. Restart

There is no checkpoint, FFRECAB or restart table in either version. A rerun starts from the beginning and DD020 is re-created, so the run is idempotent. RST-08 is correct: nothing is added. DZ01RSTV, AUD-01 and CNT-01 do not apply [OBS].

## 13. Defects & variants

| ID | Severity | Location | Description | Action (retain legacy) |
|---|---|---|---|---|
| **D-01** | Low | seq 036102, 044220, 047320-047321 | `INITIALIZE VMBFC` is added before both READs. It is neutral: the next `MOVE I-VMBFC TO VMBFC` (group, 316 → 296) overwrites every byte, and VMBFC is not read between the two statements. It costs CPU per record. The paragraph is placed after E-PROG, which is safe only because E-PROG ends with STOP RUN. The name E-INITIALIZATION is **unique** among the VMDZ*.cbl programs (grep); the pattern is the same as the inline INITIALIZE in VMDZ4230/7240/7245. | drop or log as neutral (Q-105, HLP-W4250-1) |
| **D-02** | Medium (conditional, Q-135) | seq 009602 vs VMDZ4200 seq 006100-006300 | VMDZIBFC is used in two incompatible contexts. VMDZ4200 nests it under `01 NEW-REC-FORMC` followed by `02 FILLER X(20)`, so it must start at level 02-49 (296 + 20 = the legacy C-REC-VMBFC X(316)). VMDZ4250 includes it right after `01 DATE8 REDEFINES DATE8R`, where it must start at 01. If it starts at 02, VMBFC becomes part of DATE8: compile diagnostics, and a REDEFINES larger than DATE8R. ### 15.2 New rules (provisional)

| ID | Rule |
|---|---|
| **HLP-W4250-1 NEW** | Do not emit an INITIALIZE of a record image filled by a group MOVE from the file buffer (`MOVE I-x TO <rec>`). If a team template requires a helper paragraph, append it only after a paragraph that ends with STOP RUN or GOBACK (no fall-through), and log it as neutral. |
| **CPY-W4250-1 NEW** | Keep `COPY VMDZI<xxx>` at the **same level and position** as the legacy `COPY IDMS RECORD` (01 level in WS). | **CMT-W4250-1 NEW** | Change-trace style for replaced lines: comment the original (`*COPY IDMS …`), add a `*MM/YYYY` marker and the new line, add a history line "MM/YYYY <user> : IDMS TO DB2 MIGRATION / <old> -> <new>", and set the cols 73-80 change suffix.
