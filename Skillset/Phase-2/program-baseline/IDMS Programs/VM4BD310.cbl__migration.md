# IDMS Programs/VM4BD310.cbl — IDMS → DB2 Migration Analysis

> Per-program knowledge base: legacy VM4BD310 vs manual DB2 conversion VMDZ4310. Rule IDs refer to `../../generic/` and earlier program reports. **NEW** marks a rule first proposed here (provisional ID `<CAT>-V4310-n`).
>
> - Evidence labels: [OBS] observed in source, [INF] inferred, [UNK] needs a human answer.
> - Legacy references `Lnnn` are **physical file lines** (337 lines), verified by Select-String. Seq is **not** uniform: inserted seqs 001110-001170 (history, L12-19), 008010 (L89), 030210-030220 (L312-313). Physical = seq/100 for L1-11, seq/100 + 8 for seq 001200-008000, + 9 for seq 008100-030200, + 11 from seq 030300. Examples: seq 017900 = L188 (OBTAIN FIRST), seq 023800 = L247 (IF NX-CPCRE), seq 030600 = L317.
> - DB2 references are `seq NNNNNN` (cols 1-6 of VMDZ4310, 512 lines; jumps such as 009500 → 018102 and 038800 → 063302).
> - Schema-Listing, VMBTS07.txt, DCLGEN, VMBD510I and mapping-CSV references are physical lines of those files.

| CALL PROCEDURES INFOCOMP/INFODCOM (Schema-Listing L1321-1324, L1385-1388) | — | — | ignored (PROC-01) |

Equivalence: owner fields are read for every record, so the path cannot be reduced to owner-only (contrast LRO-Z190-1) and the member must be read (contrast VM1BZ190). Collapsing NO-VMBEVEF-FND and NO-MORE-VMBEVEF into one +100 is semantically exact (both fatal) but loses the diagnostic distinction (MSG-V4310-1). The member filter moved from program loop to SQL WHERE is exact; only the "first" choice depends on set order (D-03).
