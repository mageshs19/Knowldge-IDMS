# IDMS Programs/VM1BZ310.cbl — IDMS to DB2 Migration Analysis

> **Purpose.** Knowledge base for one program pair: legacy VM1BZ310 vs the manual DB2 conversion VMDZ1310. Written for a downstream conversion engine and its reviewers.
>
> **Evidence labels:** `[OBS]` observed in source, `[INF]` inferred, `[UNK]` needs a human answer. **NEW** marks a rule first proposed here (provisional ID `<CAT>-Z310-n`).
>
> **Line references:** legacy = **physical file lines** (`L`); the sequence area steps by 10 with inserts (000041, 000191-000207, 000551-000553, 000761) and gaps (002690, 002720-002730), so it is not used. DB2 = COBOL sequence numbers (`seq NNNNNN`, = physical line × 100). Schema-Listing, VMBTS09, DCLGEN and mapping-CSV refs are physical lines.
>
> **Closest sisters:** VM1BZ130 (same subschema VMBTS09, same records VMBCOUP/VMBEVCP, explicit BINDs) and VM1BZ015 (same DZCOUPTV ⋈ DZEVCPTV join and reverse-date blocks). First **SWEEP** path in the BZ family.

## 2. Business flow (legacy, physical lines)

```
MAIN (L147-151)
  B-PROG (L153-185)
    OPEN INFILE/OUTFILE; READ INFILE (EOF → SW-FIN=1)                     L155-158
    BIND RUN-UNIT, VMBCOUP, VMBEVCP; READY AR-VMBCOUP RETRIEVAL           L161-165
    INIT-TABEL ×300: table1/table2 ← ZEROES                               L167-168, L191-196
    TABEL UNTIL SW-FIN=1 → VUL-TABEL ×10 per record                       L170-171, L203-220
      skip entry if CO-IDPRKB-IN = SPACES; ADD 1 IND2; IND2>300 → STOP02; table1(IND2) ← entry
    MAX ← IND2; SORT-TABEL/ORDER-TABEL bubble sort (EBCDIC X(16))         L173-174, L226-244
    dedup table1 → table2 (DUBBELS UNTIL table1(IND1) = ZEROES)           L176-181, L250-257
    OBTAIN FIRST VMBTL09-R01 WHERE SWEEP-VMBCOUP-VMBEVCP                  L183
  IF table2(1) NOT = 0  (always true, L-02)                               L148
     PERFORM VERWERK UNTIL LR-STATUS = 'NO-MORE-VMBCOUP'                  L149
       VERWERK (L261-273): IF LR-ERROR → STOP01
         ELSE IF NO-MORE-VMBEVCP → skip ELSE PERFORM UITGIFTE UNTIL IND3 = IND2
         IND3 ← 0; OBTAIN NEXT … WHERE SWEEP-VMBCOUP-VMBEVCP
       UITGIFTE (L278-304): ADD 1 IND3; WKY-IDISSU ← GR-IDISSU-STOCK
         IF WKY-IDISSU = table2(IND3) AND CT-RK-TEVPR OF VMBEVCP = '0060'
            build WREC (7 coupon + 10 event fields) ; WRITE OUTREC FROM WREC
  E-PROG (L308-314): CLOSE; FINISH; STOP RUN
```

**DB2 (VMDZ1310):** B-PROG identical up to the dedup (seq 020800-023300, no BIND/READY/OBTAIN). Main loop inverted: `PERFORM VERWERK UNTIL IND3 > 299 OR table2(IND3) = ZEROES OR = SPACES` (seq 019500-019800); per entry build host vars, OPEN/FETCH/CLOSE cursor `DZEVCPC1` (join + `CT_RKTEVPR = '0060'`), `ISSUANCE` per row; DISPLAY totals; CLOSE; STOP RUN (seq 019900-020600) [OBS].

## 10. LR semantics

- **SWEEP path:** `OBTAIN EACH VMBCOUP WITHIN AR-VMBCOUP` + `IF VMBCOUP-VMBEVCP IS EMPTY` (0000 → RETURN NO-VMBEVCP-FND; 1601 → NEXT) + `OBTAIN EACH VMBEVCP WITHIN set` (0307 → NO-MORE-VMBEVCP) (VMBTS09 L164-173). `LR CURRENCY NO RESET` (L5). Each LR-FOUND returns one (coupon, event) pair [OBS].
- **NO-MORE-VMBEVCP** ends one coupon; the next OBTAIN NEXT moves to the next coupon in the area [INF, LRF iteration semantics].
- **NO-VMBEVCP-FND** is not tested at L266: UITGIFTE runs with the VMBCOUP area refreshed but the VMBEVCP area **stale** (previous coupon's last event) → spurious record if that event was '0060' and the coupon's issue is selected (L-01; inverse of LRO-N595-1; Q-57) [INF].
- **Inversion in DB2:** the sweep + program-side table match becomes per-key join cursors; program filters moved into WHERE (LRO-02). Byte compare (X(16)) becomes typed compare (CHAR/DEC/DATE) → D-01, D-05.

### 15.2 New

| Rule | Statement | Guide |
|---|---|---|
| **LRO-Z310-1** **NEW** | LR `SWEEP-<OWN>-<MEM>` (area sweep + set walk) filtered program-side by an in-memory key table may become one join cursor per distinct key (owner key cols + member filters in WHERE, LRO-02).
